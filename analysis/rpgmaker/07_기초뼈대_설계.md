# 07. 기초 뼈대 설계 — RPG Maker 시리즈 장점 종합

> 최신 기준(2026-10-26): [통합 기초 설계](../../TOOL_FOUNDATION.md)와 [REA 재조사](08_REA_재조사.md)를 우선한다. 사용자 방향은 RPG Maker 제작 기능을 기준으로 Unity·Godot의 장점을 더하고, RPG Maker에 없던 기능도 UI로 제공하는 것이다. 아래 제외 목록·웹/Capacitor 전제·REA 미설치 표기는 과거 초안이며 최종 결정이 아니다. MV의 세이브를 'ID만 저장', 전투를 '화면과 완전 분리'라고 일반화한 부분도 재조사 관측에 맞춰 해석한다.

분석일 2026-10-26. 01~06 분석 문서를 종합해 **Beyond Records 전용 게임 툴의 기초 뼈대**를 제안한다. 아직 사용자 확인 전 초안이며, 구현 언어·화면 기술은 `../../ENGINE_TOOL_PLAN.md`의 제안 구조(웹 기반 + Capacitor)를 전제로 한다.

> 2026-10-26 사용자 범위 갱신: 툴은 **턴제 RPG와 2D 횡스크롤 모두 지원**한다. 아래 내용은 기존 턴제·스토리 중심 초안으로, 타일맵·필드 이동 일괄 제외는 철회한다. 공통 씬·에셋·입력·오디오·저장 기능과 장르별 실행 기능을 어떻게 나눌지 추가 설계가 필요하다. 횡스크롤용 씬 편집·이동·카메라·충돌을 설계 범위에 포함하며 타일맵·점프·중력·액션 전투의 세부 채택은 미정이다. REA는 MCP로 연결해 분석에 활용할 예정이며 아직 설치하지 않았다.

## 1. 시리즈에서 가져온 것 / 고친 것 / 버린 것

| 출처 | 가져온 장점 | 우리 뼈대에서 고친 점 |
|---|---|---|
| XP | 일러스트 중심 프론트뷰 전투, 장면 전환(freeze/transition), BGM·BGS·ME·SE 4종 사운드 구분 | 사운드는 4종 채널 + 페이드·대기 옵션 |
| VX | 메모(Note) 칸으로 데이터 확장 | 자유 텍스트 대신 **스키마로 정의하는 필드** |
| VX Ace | 특성(Feature)·사용 효과(Effect) 목록으로 일반화, 스킬별 데미지 식 | 문자열 키 사용, 효과마다 개별 대상, 조건·트리거 추가 |
| MV | 상태(Game_*)와 화면(Sprite/Window) 분리, ID만 저장하는 세이브, 명령 리스트 + 협력형 인터프리터, 웹 기반 모바일 대응 | 전역 객체 제거, 세이브 버전·마이그레이션, 전투 로직 완전 분리 |
| MZ | 플러그인 커맨드 어노테이션 → 입력 폼 자동 생성, DB 3단 레이아웃, 1클릭 테스트, 전투 테스트 | 모달 창 대신 인라인 인스펙터, 무제한 Undo, 핫리로드 |

기존 초안에서 제외한 것: 자동 조우, 장비 타입 시스템, 프레임 배열 애니메이션, 데미지 공식 `eval`, 프로토타입 덮어쓰기 플러그인, 노트 태그, 숫자 코드 식별자, 셀프 스위치, 배열 인덱스 ID. 타일맵·필드 이동은 최신 횡스크롤 지원 범위에 맞춰 다시 검토한다.

## 2. 전체 구조

```
┌──────────────── 에디터 (PC/브라우저) ────────────────┐
│ DB 에디터 │ 에피소드 에디터 │ 전투 테스트 │ 리소스 브라우저 │
│        └ 공통: 인스펙터 · Undo · 미리보기 · 핫리로드 ┘   │
└───────────────────────┬───────────────────────────────┘
                        │ 프로젝트 파일 (텍스트, Git 관리)
┌───────────────────────┴───────────────────────────────┐
│ core   (순수 로직, 화면·전역 객체 없음)                  │
│   data      스키마·레코드·참조 검증                      │
│   rules     Trait/Effect/Condition/Formula 계산          │
│   battle    BattleCore — 입력 → 이벤트 로그              │
│   story     ScriptRunner — 명령 실행 → 연출 요청          │
│   state     세이브 상태 (ID만 저장, 버전 포함)            │
├────────────────────────────────────────────────────────┤
│ runtime (화면)  scene · layer · ui · audio · input       │
│   core의 상태·이벤트 로그를 읽어 재생만 한다               │
└────────────────────────────────────────────────────────┘
   → 웹 빌드 → Capacitor → Android
```

원칙:

1. **core는 화면을 모른다.** 툴·게임·(나중에) 서버가 같은 core를 쓴다. (01, 04)
2. **전투는 먼저 계산하고 나중에 재생한다.** BattleCore가 이벤트 로그를 만들고 runtime이 연출한다. (01, 04)
3. **모든 난수는 시드 RNG로 주입한다.** (seed + 입력 기록)으로 전투를 재현·검증한다. (04)
4. **확장은 등록 방식으로 한다.** 명령·효과·특성 종류를 테이블에 등록하고, 기존 함수를 덮어쓰지 않는다. (01, 06)
5. **데이터는 텍스트 파일 + 문자열 ID.** 레코드 하나 = 파일 하나 또는 작은 묶음으로 Git 병합을 쉽게 한다. (05, 06, Godot .tres 방식)

## 3. 데이터 뼈대 (DB)

RPG Maker의 고정 탭 대신 **스키마로 데이터 종류를 정의**한다. 기본 스키마:

| 종류 | 역할 | 비고 |
|---|---|---|
| `Character` | 캐릭터(카드) 정의: 이름·일러스트·등급·속성·기본 능력치·성장표·스킬·특성 | **정의** |
| `OwnedCard` | 보유 카드: 정의 ID·레벨·돌파·호감/계약 상태 | **인스턴스** — 중복 획득·한계 돌파 가능 (02) |
| `Skill` | 비용·대상 규칙·효과 목록·연출 | 효과마다 개별 대상 (02) |
| `State` | 버프/디버프: 지속·중첩 규칙·특성·트리거 | 스택형 상태 (04) |
| `Enemy` / `Encounter` | 적 정의, 적 편성 + 전투 이벤트 페이지 | Troop 대응 (04) |
| `Element` / `Rarity` | 속성·등급 목록과 상성표 | 사용자 정의 타입 목록 (05) |
| `Episode` | 에피소드 스크립트 (4장) | |
| `Contract` | 계약 조건·효과 | 공통 Condition 사용 |
| `Asset` | 이미지·오디오 등록 정보 (GUID) | 역참조 추적 (06) |

### 규칙 4종 (공통 부품)

```
Trait     { type: "stat.rate", target: "atk", value: 1.2 }       // 지속 보정 — 합산 규칙(곱/합/집합)은 type이 정의
Effect    { type: "damage", target: "enemy.single", formula: ... } // 1회 효과 — 효과마다 대상 지정
Condition { all: [ { hpBelow: 0.5 }, { flag: "ep01.contract" } ] } // 전투·이벤트·계약·AI 공통 조건 트리
Formula   { base: "atk", mul: 2.0, minus: { stat: "def", mul: 1.0 } } // 구조화된 식 또는 안전한 소형 파서 (eval 금지)
```

- Traits 합산 파이프라인(곱·합·집합)은 MV 방식을 계승한다. (02, 04)
- 트리거(턴 시작·피격 시·처치 시 등)를 추가해 "조건부 효과"를 표현한다. (02)
- 종류(type)는 문자열이며, 에디터는 등록 테이블에서 입력 폼을 자동 생성한다. (06의 어노테이션 → 폼 방식)

## 4. 에피소드(스토리) 뼈대

MV 명령 리스트 + 협력형 인터프리터를 계승하되 비주얼노벨에 맞게 바꾼다. (03, 05)

- 저장 형식: 평면 `code/indent` 배열 대신 **트리 + 이름 있는 필드**.
- 대사 1개 = 명령 1개: `{ say: "여울", face: "smile", text: "...", voice: null }`
- 이름 있는 레이어(`bg`, `cg`, `char.left` …) — 번호 슬롯 100개 대신. 이징·트랜지션 기본 제공.
- 모든 연출 명령에 "완료까지 대기" 옵션. 시간 단위(초) 대기.
- 플래그·변수는 문자열 키(`ep01.met_yeoul`). 조건은 공통 Condition.
- 오토·스킵·백로그를 기본 기능으로.
- 전투 중 스토리는 Encounter의 전투 이벤트 페이지(조건 + 1회/매 턴)에서 같은 ScriptRunner로 호출. (04)
- 실행 전 리소스 스캔으로 사용 이미지·음원을 미리 로드. (03)
- 현재 `docs/episodes/EP01_족자_속의_기다림.md`의 대본·CG 표시 구간·BGM/효과음 지정을 이 형식으로 옮기는 것을 첫 검증 사례로 삼는다.

## 5. 전투 뼈대 (BattleCore)

MV 페이즈 머신을 계승하되 순수 로직으로 분리한다. (04)

```
start → input → turnStart → (action)* → turnEnd → input … → end
입력: { seed, party, enemies, commands[] }
출력: { result, events[] }   // events = 연출이 재생할 기록 (사용·피해·상태·대사 호출)
```

- 턴 정책(행동 순서 결정)은 교체 가능한 지점으로 연다 — 속도 순 / 고정 순서 / 카드 코스트 방식 등. (05: 커뮤니티 확장 대부분이 이 부분을 다시 짠 것)
- 덱·손패 영역은 카드 전투 방식이 확정되면 추가할 수 있도록 확장 지점으로 둔다. (전투 방식은 미정)
- 판정 순서(반격 → 반사 → 대리 → 적용), 데미지 단계(식 → 속성 → 보정 → 치명 → 분산 → 방어 → 반올림)는 MV를 기본값으로 하고 상수는 데이터로 외부화.
- 적 AI: 행동표(스킬 + Condition + 우선도) 가중 추첨을 계승.
- 밸런스 시뮬레이터: 같은 BattleCore를 화면 없이 N회 돌려 승률·평균 턴을 낸다.

## 6. 에디터 UX 뼈대

| 영역 | 기반 | 내용 |
|---|---|---|
| DB 화면 | RPG Maker (MZ) | 카테고리 → 목록 → 상세 3단 레이아웃 |
| 상세 편집 | Unity 인스펙터 | 모달 창 없이 오른쪽 인스펙터에서 바로 편집, 무제한 Undo |
| 재사용 | Unity 프리팹 | 베이스 레코드 + 변형(상속 후 일부만 덮어쓰기) |
| 에피소드 편집 | RPG Maker 이벤트 에디터 | 명령 리스트 + 카테고리 팔레트, 대사 미리보기, 분기 그래프 뷰 |
| 리소스 | Unity 드래그 앤 드롭 | 이미지·음원을 끌어다 놓기, GUID 참조, 사용처 역추적 |
| 테스트 | RPG Maker + Unity 플레이 모드 | 1클릭 실행, "여기서부터 재생", 전투 테스트, 핫리로드 |
| 내부 구조 | Godot | 씬/레이어 중첩, 시그널로 트리거 연결, 텍스트 리소스 |
| 빌드 | Godot Export Preset | Android 내보내기 설정 저장 |

## 7. 구현 우선순위 (제안)

1. **core/data + 스키마 DB 에디터 + 인스펙터** — 캐릭터·스킬 몇 개를 입력할 수 있는 최소 화면
2. **에피소드 에디터 + ScriptRunner** — EP01 파트 1을 옮겨 재생 확인
3. **BattleCore + 전투 테스트·시뮬레이터** — 전투 방식 확정 후
4. **리소스 브라우저**
5. **Android 내보내기** (Capacitor)

## 8. 미정·확인 필요

- 전투 방식(속도 순 턴제 / 카드 코스트 / 덱·손패 여부), 파티 인원, 등급·속성 체계 — 게임 기획 확정 필요
- 프로젝트 파일 단위(레코드당 1파일 vs 종류별 1파일)
- Formula를 구조화 식으로 할지, 안전한 소형 파서로 할지
- 에디터 실행 형태(브라우저 vs Electron/Tauri 데스크톱 앱)
- 후속 분석: Unity(UnityCsReference, 사용 체험)·Godot(소스) 분석 후 6장 보강
