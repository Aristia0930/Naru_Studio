# 스크립트에서 쓰는 엔진 값 (ctx 레퍼런스)

> 스크립트가 읽고 바꿀 수 있는 엔진 내부 값과 그 규칙을 모은 문서입니다. 기준: 2026-11-08, 코드와 실행 검사에서 확인한 값입니다.
> **스크립트 API나 엔진 기본값을 바꾸면 이 문서도 함께 고칩니다.** 사용법 설명은 [사용 설명서 6장](guide/README.md#6-python-스크립트)에 있습니다.

표시: **읽기** = 값을 볼 수 있음 · **쓰기** = 대입해서 바꿀 수 있음 · *게임 밖* = 에디터의 F5 스크립트 실행, F6 이벤트 테스트

새 스크립트 작성/이벤트 연결은 [작성 안내](guide/SCRIPTING.md), 현재 명령 14종의 입력·대기·중지 규칙은 [이벤트 안내](guide/EVENTS.md)에서 따라 할 수 있습니다.

**현재 공개 API 전체를 실행 예제로 연결하는 방법:** [Python 전체 가이드](guide/PYTHON_COOKBOOK.md), [이벤트 함수 완성 코드](examples/python_guide.py), [전역 훅·import 완성 코드](examples/guide_global.py). 이벤트 연결·실행 시점·인자/반환·오류·현재 없는 기능을 함께 구분합니다. 같은 폴더의 미등록 파일을 임의 import하는 기능은 제공하지 않으므로 전역 예제는 python_guide.py를 먼저 등록합니다.

## 0. 화면과 동기화되는 기본 입력 설정

새 프로젝트의 `scripts/input_settings.py`와 **게임 → 키 설정**은 같은 원본을 편집합니다. 값은 `project.json`에 중복 저장하지 않으며 `inputSettingsScript`에 실제 파일 이름을 기록합니다. 우선순위로 다른 쪽을 덮어쓰는 설정이 아닙니다.

| 변수 | 기본값·규칙 |
|---|---|
| `DEFAULT_CONTROL_ENABLED` | `True`. False면 엔진 기본 이동/조사 OFF. 대사·선택지 입력과 Python에서 입력 읽기는 유지 |
| `PLAYER_SPEED` | `240.0` px/초, 0~100000. 게임 시작 때 `ctx.player.speed`의 초기값 |
| `KEY_BINDINGS` | 기본 동작 6개→키 목록. `[]`는 OFF, 사용자 동작 추가 가능. 동작 128개·키 64개까지, 별칭·중복·이름 검증 |

기본 동작은 아래 입력 표와 같고 새 프로젝트 설정에는 `dash: ["Shift"]` 예제도 있습니다. `game.py`의 `DASH_ENABLED = False`를 True로 켜야 달리기 동작을 덧붙입니다. 전용 파일에서는 세 변수의 리터럴 대입·주석만 지원하며 함수/import/계산식은 오류로 거부합니다. 자세한 동기화·외부 파일 충돌·기존 프로젝트 이행은 [키 설정 안내](guide/INPUT_SETTINGS.md)에 있습니다.

실행 중 `ctx.input.bind`, `ctx.player.speed`, `ctx.player.default_control`은 실행 사본을 변경하고 설정 파일에는 쓰지 않습니다. 설정 변경은 저장 후 다음 게임 실행부터 적용합니다. F5/F6의 ctx.input/player가 생기는 기능은 아닙니다.

## 1. ctx는 언제 무엇을 가지나

### 공통 이벤트 호출: `ctx.run_event(event_id)`

게임 이벤트·전역 훅과 **F6 이벤트 테스트**에서 공통 이벤트 ID 문자열을 받습니다. F5 단독 실행에서는 `RuntimeError`, 없는 ID는 `KeyError`이며 Python 파일·행·traceback을 기록합니다.

```python
def run(ctx):
    ctx.run_event("recover")
    ctx.log("회복 이벤트를 예약했습니다.")
```

**예약**하고 `None`을 반환합니다. 위 로그를 먼저 남긴 뒤, Python 함수가 반환되면 예약 순서대로 실행합니다. 이벤트의 스크립트 호출 명령은 예약한 공통 이벤트의 대사·선택지·대기가 모두 끝나야 다음 명령으로 돌아갑니다. Python 함수 안에서 결과를 곧바로 읽지 마세요. 한 함수에서 최대 128개를 예약할 수 있습니다. 스크립트가 실패하면 그 함수의 예약은 실행하지 않습니다.

전역 훅의 예약은 반환 후 플레이어 조작을 막는 이벤트로 실행합니다. `on_game_start` 예약은 첫 장면 진입 뒤 실행하며, `on_scene_exit`에서 예약한 것은 취소합니다. 전역 훅의 대기 중 예약 목록은 최대 128개이고 초과하면 게임 로그에 오류를 남깁니다. `on_update`에서 매 틱 예약하지 않도록 변수·스위치로 중복을 막으세요.

공통 이벤트는 변수·데이터베이스·게임 상태를 공유합니다. 객체에서 호출한 경우 **이 객체**는 호출 객체입니다. 전역 훅과 공통 이벤트 탭에서 직접 F6를 실행하면 호출 객체가 없습니다. 중첩은 최대 32단계이며 같은 이벤트가 자신의 호출 경로에 다시 나오면 순환 오류로 멈춥니다. 순차적으로 같은 이벤트를 두 번 부르는 것은 가능합니다. 안쪽 오류는 공통 이벤트 ID·안쪽 명령 위치를 포함해 전달됩니다. F8·장면 이동은 안쪽 호출도 중지합니다. F6에서 이동·보이기·장면 이동은 로그만 남깁니다.

저장 형식: `project.json`의 `commonEvents: [{id, name, commands}]`. 호출 명령: `{"type":"call_common_event","commonEvent":"recover"}`. 이전 프로젝트에 목록이 없으면 빈 목록으로 읽습니다.

모든 스크립트 함수는 `def 함수이름(ctx):`처럼 `ctx` 하나를 받습니다.

| 어디서 불렸나 | `ctx.variables` `ctx.db` `ctx.log` | `ctx.input` | `ctx.scene` | `ctx.player` |
|---|---|---|---|---|
| 게임 중 — 전역 스크립트 `on_game_start` | 있음 | 있음 | **None** (아직 장면 전) | **None** |
| 게임 중 — `on_scene_enter` / `on_scene_exit` / `on_update` | 있음 | 있음 | 있음 | 장면에 플레이어가 있으면 있음, 없으면 None |
| 게임 중 — 이벤트의 "스크립트 호출" | 있음 | 있음 | 있음 | 위와 같음 |
| 게임 밖 — F5 실행, F6 이벤트 테스트 | 있음 | **None** | **None** | **None** |

`ctx.player`를 쓰기 전에는 `if ctx.player:`로 확인하는 것이 안전합니다.

## 2. 게임 변수 — `ctx.variables`

이벤트(변수 조작·조건 분기·데이터 → 변수·반환값 → 변수)와 **모든 스크립트가 함께 쓰는 값**입니다.

| 사용 | 설명 |
|---|---|
| `ctx.variables.get(이름, 기본값=None)` | 없으면 기본값 |
| `ctx.variables.set(이름, 값)` | 값 형식: `None`, `True/False`, 정수, 실수, 문자열. 리스트·딕셔너리 등은 `TypeError` |

- 게임을 실행할 때마다 제작툴 **게임 → 변수·스위치**에 정의한 **처음 값으로 시작**합니다 (F5·F6도 같음). 정의하지 않은 이름은 처음에 없습니다(`get`이 기본값을 돌려줌). 스위치는 `True/False` 값입니다. 장면이 바뀌어도 값은 이어집니다.
- 장면을 바꿔도 유지됩니다.
- 이벤트 규칙: 없는 변수에 `+=`, `-=`를 하거나 숫자와 비교하면 **0**으로 봅니다.
- 이름은 자유 문자열입니다. 이벤트 편집 창에서도 같은 이름으로 씁니다.

> 스크립트 안의 파이썬 변수(`count = 3`)는 게임 변수가 아닙니다. 이벤트에서 보이게 하려면 `ctx.variables.set`으로 넣거나, 스크립트 호출의 **반환값 → 변수**를 씁니다.

## 3. 플레이어 — `ctx.player` (게임 중, 플레이어가 있는 장면)

플레이어는 장면 편집 인스펙터에서 **플레이어 — 방향키로 조작**을 켠 객체입니다 (장면마다 하나).

| 이름 | 형식 | 읽기/쓰기 | 기본값·범위 | 설명 |
|---|---|---|---|---|
| `id` | str | 읽기 | | 객체 ID (예: `obj_001`) |
| `name` | str | 읽기 | | 객체 이름 |
| `x`, `y` | float | 읽기·쓰기 | 장면 편집 위치 | 왼쪽 위 좌표(픽셀). **대입은 충돌 없이 순간 이동**합니다 |
| `width`, `height` | float | 읽기 | 장면 편집 크기 | 충돌·조사 판정 크기 |
| `speed` | float | 읽기·쓰기 | 공유 설정 `PLAYER_SPEED` (없으면 **240**, px/초) | 기본 조작 이동 속도. 대각선은 √2로 나눔 |
| `facing` | str | 읽기·쓰기 | `"down"` | `"down"` `"up"` `"left"` `"right"`. 조사 방향 |
| `default_control` | bool | 읽기·쓰기 | 공유 설정 `DEFAULT_CONTROL_ENABLED` (없으면 True) | 엔진 기본 조작(방향 입력 이동 + 결정 키 조사). False면 엔진이 플레이어를 움직이지 않음 |

| 함수 | 반환 | 설명 |
|---|---|---|
| `move(dx, dy)` | bool | dx, dy 픽셀만큼 이동. **충돌**(막는 객체, 장면 가장자리), **방향 갱신**, **접촉 이벤트 판정**까지 기본 조작과 같은 규칙. 이벤트·대사 중에도 움직일 수 있음 |
| `interact()` | bool | 결정 키를 누른 것처럼 앞의 객체를 조사. 조사 이벤트를 시작했으면 True. 이벤트·대사 중이면 False |

**장면을 옮길 때**: 위치는 새 장면의 편집 위치로 돌아가고 `facing`은 `"down"`이 됩니다. `speed`와 `default_control`은 유지됩니다.

**충돌·조사 규칙** (엔진 고정값)

| 값 | 내용 |
|---|---|
| 막는 객체 | 인스펙터 **통과 — 지나갈 수 있음**이 꺼진 객체. **둘 다 통과 불가일 때만** 서로 막는다 (통과 가능한 객체는 막히지도, 막지도 않음 — 플레이어도 같음). 가장자리끼리 맞닿는 것은 겹침이 아님 |
| 경로 검사 | 한 번에 크게 움직여도 지나는 경로 전체를 검사해 벽을 건너뛰지 않음. 장면 가장자리 밖으로는 못 나감 |
| 처음부터 겹친 객체 | 막지 않음 (배치 실수로 갇히지 않게) |
| 조사 거리 | 바라보는 쪽 **16px** 안에서 가장 많이 겹친 조사 이벤트. 없으면 밟고 있는 통과 가능한 객체 |
| 플레이어 접촉 | **플레이어가** 막는 객체에 부딪히거나, 통과 가능한 객체와 겹칠 때 **새로 닿은 순간 한 번**. 밀고 있거나 겹쳐 있는 동안은 반복하지 않음 |
| 이벤트 접촉 | 위의 경우 + **객체가 움직여**(`move`) 플레이어에 부딪히거나 겹칠 때, 새로 닿은 순간 한 번. "플레이어 접촉" 객체는 객체 쪽에서 다가와 닿으면 실행되지 않음 |

## 4. 입력 — `ctx.input` (게임 중)

실제 키는 **동작 이름**으로 바뀌어 들어옵니다. 스크립트는 동작 이름으로 묻습니다.

| 사용 | 반환 | 설명 |
|---|---|---|
| `held(동작)` | bool | 지금 누르고 있는가 |
| `pressed(동작)` | bool | **이번 프레임에 새로** 눌렀는가. 한 프레임에 틱이 여러 번 돌아도 첫 틱에서만 True |
| `bind(동작, [키, ...])` | | 그 동작의 키 목록을 **바꿈** (추가가 아니라 교체). 문자열 하나도 됨. 빈 목록이면 그 동작을 끔. 새 이름이면 새 동작이 생김 |
| `keys(동작)` | list[str] | 지금 연결된 키 이름 |
| `actions()` | list[str] | 모든 동작 이름 (가나다/알파벳 순) |

- 없는 동작을 물으면 `False`나 빈 목록을 돌려줍니다 (오류 아님).
- 동시 입력: `bind("special_action", ["Shift + E", "F"])`는 Shift와 E를 함께 누르거나 F를 누르기입니다. 목록은 OR, 문자열의 `+`는 AND이며 기본 설정 `KEY_BINDINGS`에서도 같습니다. 조합은 서로 겹치지 않는 키 최대 4개, 누른 순서 무관·추가 키 허용입니다. `Keypad +`는 한 키이고 `Ctrl + Keypad +`도 지원합니다. 잘못된 조합은 `ValueError`이며 기존 배치를 보존합니다. `keys()`는 정식 이름·수식 키 우선 순서로 정리한 문자열을 반환합니다.
- 조합의 `pressed()`는 동작 전체가 꺼짐→켜짐인 첫 프레임, `held()`는 모두 누른 동안입니다. 한 키를 떼고 다시 누르면 재실행하지만 다른 대체 키가 계속 눌려 있으면 새 `pressed()`가 생기지 않습니다. 구성 키에 연결된 다른 동작도 동시에 실행할 수 있습니다. 순차 콤보·입력 시간 제한은 게임 코드에서 처리합니다. [화면 사용법·예제](guide/INPUT_SETTINGS.md#6-여러-키를-동시에-눌러-실행하기).
- 대사를 넘기는 데 쓴 결정 키는 그 프레임의 `pressed("confirm")`에 나타나지 않습니다.
- 선택지가 떠 있던 프레임의 `pressed("up")`, `pressed("down")`, `pressed("confirm")`, `pressed("cancel")`은 선택지 입력에 사용되어 스크립트에는 나타나지 않습니다. `held()`는 유지됩니다. 선택을 결정한 프레임에도 엔진 기본 이동·조사는 실행하지 않습니다. 선택지는 이벤트 명령 **선택지 표시**로 만듭니다 (기본 1번째 선택, 취소 불가).
- 기본 키·속도·조작 ON/OFF는 [키 설정 화면과 Python 전용 파일](guide/INPUT_SETTINGS.md)이 같은 값을 편집합니다. 게임 재실행 때 이 저장값을 읽습니다. `ctx.input.bind` 같은 게임 중 변경은 실행 사본만 바꾸고 원본 파일에는 쓰지 않습니다.

**기본 동작과 키 배치**

| 동작 | 기본 키 | 엔진이 쓰는 곳 |
|---|---|---|
| `up` `down` `left` `right` | `Up`/`W`, `Down`/`S`, `Left`/`A`, `Right`/`D` | 플레이어 이동 (기본 조작) |
| `confirm` | `Z`, `Return`, `Space`, `Keypad Enter` | 조사, 대사 넘기기 |
| `cancel` | `X`, `Escape` | 선택지 취소 (취소 불가이면 닫히지 않음) |

**동작 이름 규칙**: 영문 소문자로 시작, 영문 소문자·숫자·`_`, 32자 이하. 어기면 `ValueError`.

**키 이름**: SDL 키 이름이며 대소문자를 가리지 않습니다.

| 종류 | 이름 |
|---|---|
| 글자·숫자 | `A`~`Z`, `0`~`9` |
| 방향 | `Up` `Down` `Left` `Right` |
| 자주 쓰는 키 | `Space`, `Return`, `Escape`, `Tab`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown` |
| 기능 키 | `F1`~`F24` |
| 수식 키 | `Left Shift` `Right Shift` `Left Ctrl` `Right Ctrl` `Left Alt` `Right Alt` |
| 키패드 | `Keypad 0`~`Keypad 9`, `Keypad Enter` |
| **별칭** | `Enter` = `Return`, `Esc` = `Escape`, `Shift` = 왼쪽·오른쪽 Shift, `Ctrl`, `Alt`도 같은 방식 |

## 5. 장면 — `ctx.scene` (게임 중, 장면에 들어간 뒤)

이미지 에셋 ID는 에셋 추가 창에서 직접 지정하거나 목록의 **ID 변경...**으로 수정할 수 있습니다. 객체·배경의 편집 참조는 함께 갱신되지만 Python 코드의 문자열은 자동 수정하지 않습니다. 예: `day`를 `sky_day`로 바꾸면 코드의 `"day"` 비교/대입도 직접 바꾸고 게임을 다시 실행하세요. 규칙·Undo·저장은 [ID 안내](guide/ASSETS.md#id-직접-지정변경)를 참고하세요. ID 편집은 제작툴 기능이며 새 공개 Python 함수는 없습니다.

| 이름 | 형식 | 읽기/쓰기 | 설명 |
|---|---|---|---|
| `id` | str | 읽기 | 장면 ID (예: `scene_001`) |
| `name` | str | 읽기 | 장면 이름 |
| `width`, `height` | int | 읽기 | 장면 크기(픽셀). 플레이어 이동 한계 |
| `background_image` | str | 읽기·쓰기 | 현재 장면 배경 이미지 에셋 ID. `""`는 이미지 지우기(배경색만 표시). 등록된 image 에셋만 허용하며 잘못된 ID·다른 종류는 `ValueError`, 문자열 이외는 `TypeError`. 맞춤 방식·오프셋·배율·불투명도는 장면 인스펙터 설정을 유지. 즉시 실행 사본에 적용하며 대기 없음 |
| `change(장면ID, x=None, y=None, facing=None)` | | | 장면 이동을 **예약**. 지금 틱이 끝난 뒤 `on_scene_exit` → 전환 → `on_scene_enter` 순서로 바뀜. 없는 ID면 `KeyError`. `x`, `y`: 도착할 플레이어 위치(왼쪽 위 좌표, 둘 다 주거나 둘 다 생략 — 생략하면 장면 편집의 위치). `facing`: `"up"` `"down"` `"left"` `"right"` (생략하면 아래). 예: `ctx.scene.change("scene_002", 320, 400, "up")`. 이벤트 명령 "장면 이동"과 같음 |
| `ids()` | list[str] | | 프로젝트의 모든 장면 ID |

| `object(ID)` | SceneObject 또는 None | ID로 객체 찾기 (예: `ctx.scene.object("obj_002")`). ID는 인스펙터 맨 위에 보이는 값 |
| `find(이름)` | SceneObject 또는 None | 이름으로 찾기. 같은 이름이 여럿이면 장면 목록에서 먼저 나오는 것. 이름은 편집 중 바뀔 수 있으니 오래 쓸 코드는 ID 권장 |
| `objects()` | list[SceneObject] | 장면의 모든 객체 (장면 트리 순서) |

장면에 들어가면 그 장면의 이벤트가 처음부터 다시 시작됩니다. 장면 편집의 원래 상태로 돌아가고, 실행 중 바뀐 위치 등은 이어지지 않습니다.

### 5-1. 장면 객체 — `SceneObject` (`ctx.scene.object(...)` 등으로 얻음)

플레이어가 아닌 객체(NPC, 상자, 움직이는 벽…)도 플레이어와 같은 방식으로 다룹니다. 플레이어 객체를 이렇게 얻어도 됩니다 (`move`는 `ctx.player.move`와 같음).

| 이름 | 형식 | 읽기/쓰기 | 설명 |
|---|---|---|---|
| `id` | str | 읽기 | 객체 ID |
| `name` | str | 읽기 | 객체 이름 |
| `x`, `y` | float | 읽기·쓰기 | 왼쪽 위 좌표(픽셀). 대입은 충돌 없이 순간 이동 |
| `width`, `height` | float | 읽기 | 크기 |
| `passable` | bool | 읽기·쓰기 | 통과 가능 (인스펙터의 "통과"). 바꾸면 그 순간부터 충돌 규칙에 반영 |
| `visible` | bool | 읽기·쓰기 | 보이기 (인스펙터의 "보이기", 이벤트 명령 "보이기/숨기기"와 같음). `False`면 그리지 않고, 막지도 막히지도 않으며, 조사·접촉 이벤트도 실행되지 않음. 자동 실행·병렬 처리 이벤트는 숨겨도 실행됨 |
| `color` | str | 읽기·쓰기 | 색 `"#rrggbb"` (예: `"#ff8800"`). 다른 형식은 `ValueError`. 이미지 없음·누락 때의 대체 색이며 정상 이미지에 색을 곱하지 않음 |
| `image` | str | 읽기·쓰기 | `ctx.scene.object(ID).image`: 객체 이미지 에셋 ID. `""`로 지우면 색 사각형으로 복귀. 등록된 image 에셋만 허용하며 잘못된 ID·다른 종류는 `ValueError`, 문자열 이외는 `TypeError`. 실패 시 기존 값 보존. 그림 크기·배율·오프셋·기준점·회전·불투명도·뒤집기·순서·필터는 인스펙터 설정 유지. 충돌 영역은 바꾸지 않음. 즉시 적용·대기 없음 |
| `is_player` | bool | 읽기 | 이 장면의 플레이어인가 |
| `show_name` | bool | 읽기·쓰기 | 게임용 이름표 켜기. 기본 False, bool 이외는 TypeError. visible=False면 이름표도 숨김. F9 테스트 표시는 독립적 |
| `name_text` | str | 읽기·쓰기 | 이름표 문구, 기본 빈 문자열이면 객체 name 사용. 제어 문자/줄바꿈 없이 UTF-8 512바이트 이하. 타입 오류 TypeError, 길이/형식 오류 ValueError, 실패 시 기존 값 유지. 편집용 name은 바꾸지 않음 |
| `move(dx, dy)` | bool | | 충돌을 따져 이동 (아래 규칙). 객체를 찾지 못하면 `KeyError` |

```python
def on_update(ctx):
    slime = ctx.scene.object("obj_002")
    if slime and ctx.player:
        # 플레이어 쪽으로 매 프레임 1픽셀씩 다가온다
        slime.move(1 if ctx.player.x > slime.x else -1, 0)
```

- 바로 쓸 수 있는 예제(따라오기·순찰·밀기·문 열기): [docs/examples](examples/README.md)
- 장면이 바뀐 뒤 예전 장면의 객체를 쓰면 `KeyError: 장면에 없는 객체입니다`가 납니다. 객체는 쓸 때마다 `ctx.scene.object(...)`로 다시 얻는 것이 안전합니다.
- 바뀐 값은 그 실행에서만 유지되고 프로젝트 파일에는 저장되지 않습니다.

## 6. 그 밖의 ctx

| 이름 | 설명 |
|---|---|
| `ctx.busy` | 대사가 떠 있거나 조작을 막는 이벤트(조사·접촉·자동 실행)가 진행 중이면 True. 게임 밖에서는 False |
| `ctx.db.get(종류키, 항목ID)` | 데이터베이스 항목 → dict (`id`, `name`, 모든 속성). 없는 항목은 None, 없는 종류는 `KeyError`. **읽기 전용** |
| `ctx.db.ids(종류키)`, `ctx.db.types()` | 항목 ID 목록, 종류 키 목록 |
| `ctx.log(메시지)`, `ctx.warning(메시지)` | 로그 (정보/경고). 파일·행이 함께 기록됨 |
| `print(...)` | 정보 로그. `sys.stderr`로 쓰면 오류 로그 |

제작툴에서 게임을 실행하면 변수·스위치 현재 값을 **실행 변수** 패널에서 약 0.2초마다 읽기 전용으로 확인합니다. `ctx.log`·경고·예외 traceback은 실행마다 생성하는 게임 파일 로그에도 기록합니다. **게임 → 게임 로그 폴더 열기**에서 찾고, Python 오류 줄을 더블클릭하면 파일·행으로 이동합니다. 뒤따르는 명령 실패 줄은 호출 이벤트의 위치로 이동합니다. F5/F6는 별도 세션이며 게임 변수와 공유하지 않습니다. [확인 도구와 예제](guide/DEBUGGING.md)를 보세요. 이 도구를 위해 추가된 `ctx` 함수는 없습니다.

## 7. 실행 순서와 시간

| 값 | 내용 |
|---|---|
| 고정 틱 | **1/60초**. 게임 로직(훅·이벤트·이동)은 틱 단위로 진행 |
| 한 번에 따라잡는 최대 틱 | 8 (멈췄다 돌아와도 폭주하지 않도록 그 이상은 버림) |
| 즉시 명령 한도 | 이벤트 하나가 기다림 없이 연속 실행하는 명령 10000개 (무한 반복 방지) |

**게임 시작**: 전역 스크립트 읽기(최상위 코드 실행, 이름 검사) → `on_game_start` → 첫 장면 들어가기(`on_scene_enter`)

**한 틱의 순서**

1. `on_update` (등록된 전역 스크립트 순서대로)
2. 실행 조건이 맞는 자동 실행·병렬 처리 이벤트 시작 (조건은 변수 값을 보므로, 스크립트가 `ctx.variables.set`으로 스위치를 켜면 이 단계에서 시작됨)
3. 조작을 막는 이벤트 진행 (조사·접촉·자동 실행, 한 번에 하나씩)
4. 엔진 기본 조작 — `default_control`이 True이고 대사·막는 이벤트가 없을 때만: 결정 키 조사 → 방향 입력 이동
5. 이벤트 명령 "객체 이동"으로 걸어가는 객체들이 한 틱만큼 이동
6. 접촉 판정 (이번 틱의 기본 조작 이동, `move()` 이동, "객체 이동"을 합쳐서 한 번)
7. 새로 시작된 막는 이벤트의 첫 명령 실행 (대사가 바로 뜨도록)
8. 병렬 처리 이벤트 진행
9. 예약된 장면 이동 (`ctx.scene.change`, 이벤트 명령 "장면 이동")

## 8. 전역 스크립트 규칙

| 규칙 | 내용 |
|---|---|
| 등록 | 스크립트 → 전역 스크립트… 또는 목록 오른쪽 클릭. `project.json`의 `globalScripts`에 순서대로 저장 |
| 자동으로 불리는 함수 | **이름이 정확히** `on_game_start` `on_scene_enter` `on_scene_exit` `on_update`인 함수만. 이름이 조금이라도 다르면(`onUpdate`, `update`) 엔진이 부르지 않고 오류도 없음 |
| 그 밖의 함수 | 이벤트의 "스크립트 호출", 다른 함수, `import`로 **불러야** 실행됨 (예: `add_combo`) |
| 파일 최상위 코드 | 함수 밖의 코드(`WALK_SPEED = 240` 등)는 게임 시작 때 파일을 읽으며 **한 번** 실행 |
| 모듈 이름 | 파일 이름에서 `.py`를 뺀 것. 다른 스크립트에서 `import game`처럼 사용 |
| 수명 | 게임을 실행하는 동안 한 번 읽어 유지 (파이썬 전역 변수가 이어짐). 다시 실행하면 새로 읽음 |
| 이벤트에서 호출 | "스크립트 호출"의 파일이 전역 스크립트면 **실행 중인 모듈**의 함수를 부름. 게임 밖(F6)에서는 매번 새로 읽음 |
| 변수 이름 겹침 | 전역 스크립트끼리 **파일 최상위에서 대입한 이름**이 같으면 오류. 훅 함수, `import`한 이름, `_`로 시작하는 이름은 제외 |
| 표준 모듈 이름 | 파일 이름이 Python 표준 모듈과 같으면 오류 (예: `random.py`) |
| 훅 오류 | 로그에 한 번 보고하고, 그 실행 동안 **그 스크립트의 그 훅만** 다시 부르지 않음 |

## 게임 소리 — ctx.audio

`audio`는 실제 게임에서 사용하는 소리 재생기입니다. F5/F6에서는 `ctx.audio`가 None입니다. 게임의 on_game_start(첫 장면 전 포함)·on_scene_enter·on_scene_exit·on_update와 이벤트 함수에서 사용합니다. [전체 사용법·예제·수동 확인](guide/AUDIO.md).

| 함수 | 인자·기본값 | 반환·규칙 |
|---|---|---|
| `ctx.audio.play_bgm(asset_id, volume=100, loop=True)` | 등록한 WAV/MP3 소리 ID 문자열, 유한한 음량 0~100, 반복 bool | None. 기존 BGM 대신 처음부터 재생. 실패하면 이전 BGM 유지 |
| `ctx.audio.stop_bgm(fade_seconds=0)` | 유한한 0~60초, 0이면 즉시 | None. 페이드 정지 예약 후 바로 반환 |
| `ctx.audio.play_se(asset_id, volume=100)` | 등록한 소리 ID 문자열, 유한한 0~100 | None. 한 번 재생하며 앞 효과음과 겹침. 최대 16개 |
| `ctx.audio.stop_se()` | 없음 | None. 효과음 모두 즉시 정지 |

호출은 재생 완료를 기다리지 않습니다. 장면 전환·이벤트 종료/취소에도 유지하며 게임 종료 시 해제합니다. 같은 곡을 재호출하면 다시 시작합니다. 매 틱 on_update에서 play_bgm을 호출하지 마세요. 페이드 중 새 BGM 재생은 이전 곡을 대신합니다.

없는 ID/소리 이외 종류·범위/NaN/무한대는 ValueError, 타입 오류는 TypeError, 누락/손상 파일·장치·동시 한도 실패는 RuntimeError입니다. 파일·행·traceback이 보존됩니다. 파일당 64 MiB, 디코딩 PCM 128 MiB, 게임 동시 PCM 준비/보유 256 MiB 한도입니다. 현재 동기 전체 디코딩이며 스트리밍·피치·일시정지·위치 음향은 아직 없습니다. 이벤트의 소리 명령은 F6에서 로그만 남깁니다. 복사 가능한 파일은 [audio_demo.py](examples/audio/scripts/audio_demo.py)이며 `run(ctx)`/`fade(ctx)`/`stop_effects(ctx)`를 이벤트 스크립트 호출로 연결합니다.


## 객체 이름표와 테스트 표시

`ctx.scene.object(ID).show_name`은 게임용 이름표 bool(기본 False), `.name_text`는 문구 str(기본 빈 글자)입니다. 빈 문구는 객체의 읽기 전용 `.name`을 그대로 표시합니다. 플레이어도 `ctx.scene.object(ctx.player.id)`로 얻어 같은 속성을 사용합니다. 숨긴 객체는 이름표도 숨기며 문구 변경은 name/ID·충돌·이벤트에 영향을 주지 않습니다.

게임 실행 사본에 즉시 적용하고 대기하지 않습니다. 장면 재진입/게임 재시작은 편집값이며 F5/F6과 첫 장면 전 on_game_start의 ctx.scene은 None입니다. show_name은 bool, name_text는 str만 허용하고 타입 오류는 TypeError입니다. 문구는 줄바꿈/제어 문자 없이 UTF-8 512바이트 이하이며 범위/형식 오류 ValueError, UTF-8로 변환 불가능한 문자열은 UnicodeEncodeError입니다. 실패하면 이전 값을 유지합니다. 오래된 객체 핸들은 KeyError가 날 수 있습니다. 이벤트 함수의 ctx·None 반환/호출 설정은 [이름표 가이드](guide/NAMEPLATES.md), 완성 코드는 [nameplates.py](examples/nameplates/scripts/nameplates.py)에 있습니다.

테스트용 전체 표시(F9/--debug-object-names)는 위 두 속성과 별개이며 Python 공개 속성으로 제공하지 않습니다. F9는 게임에서 예약한 키로 ctx.input에 전달하지 않습니다. 제작툴 창 F9의 데이터베이스 기능은 그대로입니다.


## 이름표 배경·위치

SceneObject의 `name_background_transparent`(bool, 기본 False), `name_background_color`(str, 기본 "#0c1018"), `name_position`(str, 기본 "above")은 읽기·쓰기가 가능합니다. 색은 #rrggbb 7자, 위치는 "above"/"below"만 허용하며 타입 오류 TypeError, 잘못된 색/위치 ValueError로 이전 값을 유지합니다. 잘못된 Unicode 문자열은 변환 오류가 납니다.

투명은 배경만 없애고 저장된 색을 지우지 않습니다. 색을 바꿔도 투명 여부는 자동으로 바뀌지 않으므로 색 배경을 표시하려면 name_background_transparent=False도 지정합니다. 배경은 알파 210/255, 완전 투명은 True입니다. 위치는 그림의 회전/크기/기준점/오프셋 경계 기준이고 누락 이미지는 충돌 사각형 기준입니다. 화면 가장자리 보정을 우선합니다. F9 테스트 표시에는 개별 스타일을 적용하지 않습니다.

게임 중 즉시 적용·대기 없음·편집 원본 보존·재진입/재시작 때 초기화·F5/F6은 ctx.scene=None 규칙이 같습니다. [API와 완성 예제](guide/NAMEPLATES.md), [스타일 예제 파일](examples/nameplate-style/scripts/nameplates.py)의 transparent_above/colored_below를 스크립트 호출에 연결합니다. ctx 인자·None 반환·전역 등록 불필요입니다.
