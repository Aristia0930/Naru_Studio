# 스크립트에서 쓰는 엔진 값 (ctx 레퍼런스)

> 스크립트가 읽고 바꿀 수 있는 엔진 내부 값과 그 규칙을 모은 문서입니다. 기준: 2026-10-27, 코드에서 확인한 값입니다.
> **스크립트 API나 엔진 기본값을 바꾸면 이 문서도 함께 고칩니다.** 사용법 설명은 [사용 설명서 6장](guide/README.md#6-python-스크립트)에 있습니다.

표시: **읽기** = 값을 볼 수 있음 · **쓰기** = 대입해서 바꿀 수 있음 · *게임 밖* = 에디터의 F5 스크립트 실행, F6 이벤트 테스트

---

## 1. ctx는 언제 무엇을 가지나

모든 스크립트 함수는 `def 함수이름(ctx):`처럼 `ctx` 하나를 받습니다.

| 어디서 불렸나 | `ctx.variables` `ctx.db` `ctx.log` | `ctx.input` | `ctx.scene` | `ctx.player` |
|---|---|---|---|---|
| 게임 중 — 전역 스크립트 `on_game_start` | 있음 | 있음 | **None** (아직 장면 전) | **None** |
| 게임 중 — `on_scene_enter` / `on_scene_exit` / `on_update` | 있음 | 있음 | 있음 | 장면에 플레이어가 있으면 있음, 없으면 None |
| 게임 중 — 이벤트의 "스크립트 호출" | 있음 | 있음 | 있음 | 위와 같음 |
| 게임 밖 — F5 실행, F6 이벤트 테스트 | 있음 | **None** | **None** | **None** |

`ctx.player`를 쓰기 전에는 `if ctx.player:`로 확인하는 것이 안전합니다.

---

## 2. 게임 변수 — `ctx.variables`

이벤트(변수 조작·조건 분기·데이터 → 변수·반환값 → 변수)와 **모든 스크립트가 함께 쓰는 값**입니다.

| 사용 | 설명 |
|---|---|
| `ctx.variables.get(이름, 기본값=None)` | 없으면 기본값 |
| `ctx.variables.set(이름, 값)` | 값 형식: `None`, `True/False`, 정수, 실수, 문자열. 리스트·딕셔너리 등은 `TypeError` |

- 게임을 실행할 때마다 **비어 있는 상태로 시작**합니다. F5·F6도 매번 비어 있습니다. 프로젝트 공용 변수 정의(초기값)는 아직 없습니다 (ROADMAP P2).
- 장면을 바꿔도 유지됩니다.
- 이벤트 규칙: 없는 변수에 `+=`, `-=`를 하거나 숫자와 비교하면 **0**으로 봅니다.
- 이름은 자유 문자열입니다. 이벤트 편집 창에서도 같은 이름으로 씁니다.

> 스크립트 안의 파이썬 변수(`count = 3`)는 게임 변수가 아닙니다. 이벤트에서 보이게 하려면 `ctx.variables.set`으로 넣거나, 스크립트 호출의 **반환값 → 변수**를 씁니다.

## 3. 플레이어 — `ctx.player` (게임 중, 플레이어가 있는 장면)

플레이어는 장면 편집 인스펙터에서 **플레이어 — 방향키로 조작**을 켠 객체입니다 (장면마다 하나).

| 이름 | 형식 | 읽기/쓰기 | 기본값·범위 | 설명 |
|---|---|---|---|---|
| `id` | str | 읽기 | | 객체 ID (예: `obj_001`) |
| `name` | str | 읽기 | | 객체 이름 |
| `x`, `y` | float | 읽기·쓰기 | 장면 편집 위치 | 왼쪽 위 좌표(픽셀). **대입은 충돌 없이 순간 이동**합니다 |
| `width`, `height` | float | 읽기 | 장면 편집 크기 | 충돌·조사 판정 크기 |
| `speed` | float | 읽기·쓰기 | **240** (픽셀/초), 0 이상 | 기본 조작 이동 속도. 대각선은 √2로 나눔 |
| `facing` | str | 읽기·쓰기 | `"down"` | `"down"` `"up"` `"left"` `"right"`. 조사 방향 |
| `default_control` | bool | 읽기·쓰기 | `True` | 엔진 기본 조작(방향 입력 이동 + 결정 키 조사). `False`면 엔진이 플레이어를 움직이지 않음 |

| 함수 | 반환 | 설명 |
|---|---|---|
| `move(dx, dy)` | bool | dx, dy 픽셀만큼 이동. **충돌**(막는 객체, 장면 가장자리), **방향 갱신**, **접촉 이벤트 판정**까지 기본 조작과 같은 규칙. 이벤트·대사 중에도 움직일 수 있음 |
| `interact()` | bool | 결정 키를 누른 것처럼 앞의 객체를 조사. 조사 이벤트를 시작했으면 True. 이벤트·대사 중이면 False |

**장면을 옮길 때**: 위치는 새 장면의 편집 위치로 돌아가고 `facing`은 `"down"`이 됩니다. `speed`와 `default_control`은 유지됩니다.

**충돌·조사 규칙** (엔진 고정값)

| 값 | 내용 |
|---|---|
| 막는 객체 | 인스펙터 **통과 — 지나갈 수 있음**이 꺼진 객체. **둘 다 통과 불가일 때만** 서로 막는다 (통과 가능한 객체는 막히지도, 막지도 않음 — 플레이어도 같음). 가장자리끼리 맞닿는 것은 겹침이 아님 |
| 경로 검사 | 한 번에 크게 움직여도 지나는 경로 전체를 검사해 벽을 건너뛰지 않음. 장면 가장자리 밖으로는 못 나감 |
| 처음부터 겹친 객체 | 막지 않음 (배치 실수로 갇히지 않게) |
| 조사 거리 | 바라보는 쪽 **16px** 안에서 가장 많이 겹친 조사 이벤트. 없으면 밟고 있는 통과 가능한 객체 |
| 플레이어 접촉 | **플레이어가** 막는 객체에 부딪히거나, 통과 가능한 객체와 겹칠 때 **새로 닿은 순간 한 번**. 밀고 있거나 겹쳐 있는 동안은 반복하지 않음 |
| 이벤트 접촉 | 위의 경우 + **객체가 움직여**(`move`) 플레이어에 부딪히거나 겹칠 때, 새로 닿은 순간 한 번. "플레이어 접촉" 객체는 객체 쪽에서 다가와 닿으면 실행되지 않음 |

## 4. 입력 — `ctx.input` (게임 중)

실제 키는 **동작 이름**으로 바뀌어 들어옵니다. 스크립트는 동작 이름으로 묻습니다.

| 사용 | 반환 | 설명 |
|---|---|---|
| `held(동작)` | bool | 지금 누르고 있는가 |
| `pressed(동작)` | bool | **이번 프레임에 새로** 눌렀는가. 한 프레임에 틱이 여러 번 돌아도 첫 틱에서만 True |
| `bind(동작, [키, ...])` | | 그 동작의 키 목록을 **바꿈** (추가가 아니라 교체). 문자열 하나도 됨. 빈 목록이면 그 동작을 끔. 새 이름이면 새 동작이 생김 |
| `keys(동작)` | list[str] | 지금 연결된 키 이름 |
| `actions()` | list[str] | 모든 동작 이름 (가나다/알파벳 순) |

- 없는 동작을 물으면 `False`나 빈 목록을 돌려줍니다 (오류 아님).
- 대사를 넘기는 데 쓴 결정 키는 그 프레임의 `pressed("confirm")`에 나타나지 않습니다.
- 키 배치는 게임을 실행하는 동안 유지되고, 다시 실행하면 아래 기본값으로 돌아갑니다. 그래서 보통 `on_game_start`에서 바꿉니다.

**기본 동작과 키 배치**

| 동작 | 기본 키 | 엔진이 쓰는 곳 |
|---|---|---|
| `up` `down` `left` `right` | `Up`/`W`, `Down`/`S`, `Left`/`A`, `Right`/`D` | 플레이어 이동 (기본 조작) |
| `confirm` | `Z`, `Return`, `Space`, `Keypad Enter` | 조사, 대사 넘기기 |
| `cancel` | `X`, `Escape` | (아직 쓰는 곳 없음) |

**동작 이름 규칙**: 영문 소문자로 시작, 영문 소문자·숫자·`_`, 32자 이하. 어기면 `ValueError`.

**키 이름**: SDL 키 이름이며 대소문자를 가리지 않습니다.

| 종류 | 이름 |
|---|---|
| 글자·숫자 | `A`~`Z`, `0`~`9` |
| 방향 | `Up` `Down` `Left` `Right` |
| 자주 쓰는 키 | `Space`, `Return`, `Escape`, `Tab`, `Backspace`, `Delete`, `Insert`, `Home`, `End`, `PageUp`, `PageDown` |
| 기능 키 | `F1`~`F12` |
| 수식 키 | `Left Shift` `Right Shift` `Left Ctrl` `Right Ctrl` `Left Alt` `Right Alt` |
| 키패드 | `Keypad 0`~`Keypad 9`, `Keypad Enter` |
| **별칭** | `Enter` = `Return`, `Esc` = `Escape`, `Shift` = 왼쪽·오른쪽 Shift, `Ctrl`, `Alt`도 같은 방식 |

## 5. 장면 — `ctx.scene` (게임 중, 장면에 들어간 뒤)

| 이름 | 형식 | 읽기/쓰기 | 설명 |
|---|---|---|---|
| `id` | str | 읽기 | 장면 ID (예: `scene_001`) |
| `name` | str | 읽기 | 장면 이름 |
| `width`, `height` | int | 읽기 | 장면 크기(픽셀). 플레이어 이동 한계 |
| `change(장면ID, x=None, y=None, facing=None)` | | | 장면 이동을 **예약**. 지금 틱이 끝난 뒤 `on_scene_exit` → 전환 → `on_scene_enter` 순서로 바뀜. 없는 ID면 `KeyError`. `x`, `y`: 도착할 플레이어 위치(왼쪽 위 좌표, 둘 다 주거나 둘 다 생략 — 생략하면 장면 편집의 위치). `facing`: `"up"` `"down"` `"left"` `"right"` (생략하면 아래). 예: `ctx.scene.change("scene_002", 320, 400, "up")`. 이벤트 명령 "장면 이동"과 같음 |
| `ids()` | list[str] | | 프로젝트의 모든 장면 ID |

| `object(ID)` | SceneObject 또는 None | ID로 객체 찾기 (예: `ctx.scene.object("obj_002")`). ID는 인스펙터 맨 위에 보이는 값 |
| `find(이름)` | SceneObject 또는 None | 이름으로 찾기. 같은 이름이 여럿이면 장면 목록에서 먼저 나오는 것. 이름은 편집 중 바뀔 수 있으니 오래 쓸 코드는 ID 권장 |
| `objects()` | list[SceneObject] | 장면의 모든 객체 (장면 트리 순서) |

장면에 들어가면 그 장면의 이벤트가 처음부터 다시 시작됩니다. 장면 편집의 원래 상태로 돌아가고, 실행 중 바뀐 위치 등은 이어지지 않습니다.

### 5-1. 장면 객체 — `SceneObject` (`ctx.scene.object(...)` 등으로 얻음)

플레이어가 아닌 객체(NPC, 상자, 움직이는 벽…)도 플레이어와 같은 방식으로 다룹니다. 플레이어 객체를 이렇게 얻어도 됩니다 (`move`는 `ctx.player.move`와 같음).

| 이름 | 형식 | 읽기/쓰기 | 설명 |
|---|---|---|---|
| `id` | str | 읽기 | 객체 ID |
| `name` | str | 읽기 | 객체 이름 |
| `x`, `y` | float | 읽기·쓰기 | 왼쪽 위 좌표(픽셀). 대입은 충돌 없이 순간 이동 |
| `width`, `height` | float | 읽기 | 크기 |
| `passable` | bool | 읽기·쓰기 | 통과 가능 (인스펙터의 "통과"). 바꾸면 그 순간부터 충돌 규칙에 반영 |
| `visible` | bool | 읽기·쓰기 | 보이기 (인스펙터의 "보이기", 이벤트 명령 "보이기/숨기기"와 같음). `False`면 그리지 않고, 막지도 막히지도 않으며, 조사·접촉 이벤트도 실행되지 않음. 자동 실행·병렬 처리 이벤트는 숨겨도 실행됨 |
| `color` | str | 읽기·쓰기 | 색 `"#rrggbb"` (예: `"#ff8800"`). 다른 형식은 `ValueError`. 이미지 기능 전까지의 겉모습 |
| `is_player` | bool | 읽기 | 이 장면의 플레이어인가 |
| `move(dx, dy)` | bool | | 충돌을 따져 이동 (아래 규칙). 객체를 찾지 못하면 `KeyError` |

```python
def on_update(ctx):
    slime = ctx.scene.object("obj_002")
    if slime and ctx.player:
        # 플레이어 쪽으로 매 프레임 1픽셀씩 다가온다
        slime.move(1 if ctx.player.x > slime.x else -1, 0)
```

- 바로 쓸 수 있는 예제(따라오기·순찰·밀기·문 열기): [docs/examples](examples/README.md)
- 장면이 바뀐 뒤 예전 장면의 객체를 쓰면 `KeyError: 장면에 없는 객체입니다`가 납니다. 객체는 쓸 때마다 `ctx.scene.object(...)`로 다시 얻는 것이 안전합니다.
- 바뀐 값은 그 실행에서만 유지되고 프로젝트 파일에는 저장되지 않습니다.

## 6. 그 밖의 ctx

| 이름 | 설명 |
|---|---|
| `ctx.busy` | 대사가 떠 있거나 조작을 막는 이벤트(조사·접촉·자동 실행)가 진행 중이면 True. 게임 밖에서는 False |
| `ctx.db.get(종류키, 항목ID)` | 데이터베이스 항목 → dict (`id`, `name`, 모든 속성). 없는 항목은 None, 없는 종류는 `KeyError`. **읽기 전용** |
| `ctx.db.ids(종류키)`, `ctx.db.types()` | 항목 ID 목록, 종류 키 목록 |
| `ctx.log(메시지)`, `ctx.warning(메시지)` | 로그 (정보/경고). 파일·행이 함께 기록됨 |
| `print(...)` | 정보 로그. `sys.stderr`로 쓰면 오류 로그 |

## 7. 실행 순서와 시간

| 값 | 내용 |
|---|---|
| 고정 틱 | **1/60초**. 게임 로직(훅·이벤트·이동)은 틱 단위로 진행 |
| 한 번에 따라잡는 최대 틱 | 8 (멈췄다 돌아와도 폭주하지 않도록 그 이상은 버림) |
| 즉시 명령 한도 | 이벤트 하나가 기다림 없이 연속 실행하는 명령 10000개 (무한 반복 방지) |

**게임 시작**: 전역 스크립트 읽기(최상위 코드 실행, 이름 검사) → `on_game_start` → 첫 장면 들어가기(`on_scene_enter`)

**한 틱의 순서**

1. `on_update` (등록된 전역 스크립트 순서대로)
2. 조작을 막는 이벤트 진행 (조사·접촉·자동 실행, 한 번에 하나씩)
3. 엔진 기본 조작 — `default_control`이 True이고 대사·막는 이벤트가 없을 때만: 결정 키 조사 → 방향 입력 이동
4. 이벤트 명령 "객체 이동"으로 걸어가는 객체들이 한 틱만큼 이동
5. 접촉 판정 (이번 틱의 기본 조작 이동, `move()` 이동, "객체 이동"을 합쳐서 한 번)
6. 새로 시작된 막는 이벤트의 첫 명령 실행 (대사가 바로 뜨도록)
7. 병렬 처리 이벤트 진행
8. 예약된 장면 이동 (`ctx.scene.change`, 이벤트 명령 "장면 이동")

## 8. 전역 스크립트 규칙

| 규칙 | 내용 |
|---|---|
| 등록 | 스크립트 → 전역 스크립트… 또는 목록 오른쪽 클릭. `project.json`의 `globalScripts`에 순서대로 저장 |
| 자동으로 불리는 함수 | **이름이 정확히** `on_game_start` `on_scene_enter` `on_scene_exit` `on_update`인 함수만. 이름이 조금이라도 다르면(`onUpdate`, `update`) 엔진이 부르지 않고 오류도 없음 |
| 그 밖의 함수 | 이벤트의 "스크립트 호출", 다른 함수, `import`로 **불러야** 실행됨 (예: `add_combo`) |
| 파일 최상위 코드 | 함수 밖의 코드(`WALK_SPEED = 240` 등)는 게임 시작 때 파일을 읽으며 **한 번** 실행 |
| 모듈 이름 | 파일 이름에서 `.py`를 뺀 것. 다른 스크립트에서 `import game`처럼 사용 |
| 수명 | 게임을 실행하는 동안 한 번 읽어 유지 (파이썬 전역 변수가 이어짐). 다시 실행하면 새로 읽음 |
| 이벤트에서 호출 | "스크립트 호출"의 파일이 전역 스크립트면 **실행 중인 모듈**의 함수를 부름. 게임 밖(F6)에서는 매번 새로 읽음 |
| 변수 이름 겹침 | 전역 스크립트끼리 **파일 최상위에서 대입한 이름**이 같으면 오류. 훅 함수, `import`한 이름, `_`로 시작하는 이름은 제외 |
| 표준 모듈 이름 | 파일 이름이 Python 표준 모듈과 같으면 오류 (예: `random.py`) |
| 훅 오류 | 로그에 한 번 보고하고, 그 실행 동안 **그 스크립트의 그 훅만** 다시 부르지 않음 |

## 9. 아직 스크립트로 못 하는 것

- 객체 숨기기/보이기, 크기 바꾸기, 실행 중 객체 만들기/지우기, 객체의 이벤트·실행 조건 바꾸기
- 스크립트에서 대사를 띄우고 기다리기, 대기 (`async def` — 지금은 명확한 오류로 거부)
- 스크립트에서 이벤트 시작, 공통 이벤트 호출
- 데이터베이스 값 바꾸기 (읽기 전용)
- 게임 변수에 리스트·딕셔너리 저장, 세이브/로드
- 이미지·소리
