# 1차 배포 완료 후 다시 검토할 기능

사용자 요청: **순서 19 게임 내보내기와 1차 배포 완주까지 먼저 개발**한 뒤, 그때의 실제 기능·문제·성능을 다시 조사하고 이 목록의 필요성·우선순위·구현 방법을 함께 정한다. 아래는 검토할 요구와 후보이며 구현 완료나 확정 설계가 아니다. 개발 도중 발견한 실제 오류를 고치는 것과 후속 대형 기능을 선행 구현하는 것은 구분한다.

## 배포까지 완료했다는 기준

1. 타이틀 → 플레이 → 저장 → 종료 → 재실행·로드 → 엔딩을 검증한다.
2. 순서 19의 실제 내보내기로 만든 결과가 개발 도구가 없는 다른 PC에서 실행되고 필요한 이미지·음원·Python·글꼴 및 저장/로그 경로가 동작하는지 확인한다. 첫 배포 대상은 Windows다.
3. 이후 이 문서의 각 항목을 그 시점의 구현과 다시 대조한다. 사용자에게 확인받은 범위와 미확인 범위를 구분하고, 측정·위험·의존성·사용성에 따라 세부 계획을 새로 정한다.

19번의 최소 실행 묶음·배포 검증은 그대로 수행한다. 아래의 고급 패킹·보호 기능을 만들어야만 19번을 시작할 수 있다고 전제하지 않는다.

## 1. 에셋 패킹과 보호

**요구:** 배포 시 다수의 이미지·음원 등 리소스를 묶고, 쉽게 파일을 열거나 수정·추출하는 일을 어렵게 하고 싶다.

- 배포용 묶음과 읽기 인터페이스(VFS), 인덱스·버전·파일별 위치/무결성, 압축 여부·형식은 그때 기존 배포 구조와 비교해 결정한다. 편집용 프로젝트 원본은 유지하고 배포 시 결과물을 만든다. 큰 음원은 로딩 중 전체를 메모리에 강제하지 않도록 스트리밍·임의 접근도 검토한다.
- PNG·MP3처럼 이미 압축된 파일은 다시 묶어도 반드시 작아지지 않는다. 파일 수·설치 크기·패킹 시간·첫 로딩·메모리를 실제로 측정하고 개별 압축 여부를 고른다.
- 리소스 암호화·난독화와 변조 감지/서명은 서로 다른 기능으로 검토한다. 인증된 암호화나 디지털 서명은 검증된 구현을 사용하고 키 생성·보관·교체·업데이트·손상 복구를 함께 설계한다. 개인 경로·원본·자격증명·서버 비밀 키는 배포본에 넣지 않는다.
- **보호의 한계:** 이용자의 PC에서 오프라인으로 실행하려면 그 PC에서 복호화하거나 해석할 수 있어야 하므로, 추출·역분석을 완전히 막는다고 약속하지 않는다. 프로그램에 고정된 복호화 키도 추출될 수 있다. 무단 추출을 어렵게 하는 보호 수준·온라인 확인 필요 여부·오프라인 플레이와 사용자의 불편 사이에서 나중에 선택한다. [OWASP의 키 보관 설명](https://mas.owasp.org/MASTG/knowledge/android/MASVS-STORAGE/MASTG-KNOW-0047/), [변조·역분석 대응 설명](https://mas.owasp.org/MASVS/11-MASVS-RESILIENCE/).
- Python 코드, 이미지, 음원, DB, 세이브·설정·로그의 보호 대상과 복구/호환 범위를 따로 결정한다. 앱에 들어간 값은 서버 비밀을 안전하게 보관할 장소로 취급하지 않는다. 오프라인 게임의 개인 세이브와 온라인 서버 인증·권한도 별개다.
- **확인할 기준:** 원본 보존, 다른 PC의 오프라인 실행, 이미지·음원·스크립트·글꼴 동일 결과, 잘못된/변조된/누락된 묶음의 명확한 오류, 업데이트·버전 호환, 압축률·로드 시간·메모리·성능 비교. 암호화는 권한 없는 단순 열람·추출을 어렵게 하는 목표와 한계를 명시한다.

## 2. 텍스처 아틀라스와 성능 최적화

**요구:** 많은 스프라이트·타일을 효율적으로 묶고 게임의 실행 성능과 빌드 크기를 개선하고 싶다.

- 그때의 타일맵·애니메이션·렌더러를 조사한 뒤, 에디터 또는 빌드에서 여러 이미지를 아틀라스로 생성하는 옵션을 검토한다. 원본/에셋 ID를 유지하며 배포용 아틀라스와 좌표 매핑을 별도로 만든다.
- 이미지 크기·최대 텍스처 크기·분할, 여백/padding과 가장자리 번짐, 알파·필터, 기준점·회전·잘린 여백, 애니메이션 프레임, 정렬/겹침 순서·투명도·메모리 상주 범위를 다룬다. 큰 아틀라스 하나가 항상 유리한 것은 아니므로 장면/그룹별 분할도 평가한다.
- 현재 SDL3 2D 렌더러는 자체 배칭을 사용한다. 아틀라스만 만든다고 드로우 콜 감소나 FPS 향상이 자동으로 보장되지는 않으므로 실제 렌더러의 텍스처 전환·그리기 순서·CPU/GPU와 메모리를 측정한다. [SDL3 공식 설명](https://wiki.libsdl.org/SDL3/README-migration).
- **확인할 기준:** 같은 장면의 처리 전후 프레임 시간·로딩·메모리·텍스처 전환/가능한 드로우 콜·배포 크기를 비교한다. 투명 가장자리·이미지 배치·충돌·애니메이션 프레임·순서가 달라지지 않아야 하며 작은 맵과 대량 장면을 모두 확인한다.

## 3. 인게임 콘솔·디버그 오버레이

**요구:** Ctrl+R 테스트 플레이 중 변수 값을 바꾸고 Python을 즉석 실행하며 FPS·메모리·활성 객체 수를 확인한다.

- 현재 제공하는 것은 제작툴의 **읽기 전용 실행 변수 패널**, 오류 위치 이동·파일 로그다. 이것을 게임 내부 콘솔이나 변수 강제 변경 기능이 구현된 것으로 계산하지 않는다.
- 게임 상태를 멈추거나 유지할지, 변수 쓰기의 타입/실패·적용 시점, 일시 실행 코드의 `ctx`·오류/traceback·안전한 수명, 성능 수치의 갱신 간격과 의미를 나중에 결정한다. 편집 원본·세이브·실행 사본을 구분한다.
- 개발용 권한·활성화 수단과 일반 배포본에서의 제거/비활성, 입력 포커스·기존 키 충돌, 로그의 개인 정보·민감값 처리를 함께 설계한다. 클라이언트 콘솔은 서버 권한의 대체 수단이 아니다.
- **확인할 기준:** 테스트 중 입력·변수 변경·오류 보고·콘솔 닫기 후 게임 조작 복귀, FPS/메모리/객체 수의 출처와 실제 수치 대조, 일반 배포본의 콘솔 접근 차단과 편집 원본 보존.

## 4. 이벤트 호출 스택과 타임라인

**요구:** 병렬 처리·공통 이벤트·Python 호출이 어떤 순서로 실행되고 어디에서 대기/실패했는지 추적하고 싶다.

- 현재는 로그의 이벤트 오류 위치 이동·공통 이벤트 호출 경로와 변수 패널이 있다. 실행 중인 모든 호출의 실시간 스택·시간순 타임라인·단계 실행이 구현된 것은 아니다.
- 실행 인스턴스/장면/객체/공통 이벤트/명령의 식별, 시작·대기·재개·완료·취소·실패 시각, 병렬 실행의 관계, Python 오류·호출 경로, 중첩 분기, 필터와 명령 위치 이동을 검토한다. 무한 기록을 피하기 위한 크기 제한·링 버퍼·기록 중지/내보내기와 실행 성능 영향도 정한다.
- **확인할 기준:** 병렬 이벤트 둘과 중첩 공통 이벤트, 선택/대기, Python 예외, F8·장면 이동의 실행 순서와 실제 상태 일치. 잘못된 이전 로그로 수정된 원본의 엉뚱한 명령으로 이동하지 않고 기록량 제한이 동작해야 한다.

## 5. 사운드 뱅크·오디오 버스/믹서

**요구:** 마스터와 BGM·SFX·UI 등의 음량 그룹을 따로 조절하고, 같은 효과음이 짧은 간격으로 많이 재생될 때 중첩을 관리한다.

- 현재 BGM 한 곡·음량/반복/페이드 정지, 효과음 재생·전체 정지, 최대 16개 동시 효과음은 구현되어 있다. 마스터·BGM·SFX·UI 개별 버스, 사운드 뱅크, 음성 우선순위/교체 정책은 현재 기능으로 표시하지 않는다.
- 프로젝트 기본 음량과 플레이어 개인 설정의 저장 위치, 버스 계층과 최종 음량, 일시정지·장면 전환·페이드 규칙, 사운드 뱅크의 등록·미리듣기·불러오기/해제, 긴 음원 스트리밍과 메모리 사용을 검토한다.
- 동시 음성 한도에 도달했을 때 새 소리를 거부할지, 오래되거나 우선순위가 낮은 소리를 교체할지(voice stealing), 동일 효과음 재생 간격·그룹별 한도를 어떻게 정할지 결정한다. 중첩 제한만으로 찢어짐이 반드시 해결되는 것은 아니므로 신호 합산·헤드룸·클리핑과 부드러운 전환도 함께 검증한다.
- **확인할 기준:** 버스별·마스터 음량 변화가 의도한 소리에만 반영되고 개인 설정이 재시작 후 유지. 효과음 동시 한도·우선순위·짧은 간격 재생·페이드·정지/장면 이동·오디오 장치 오류를 자동 검증하고 실제 스피커/헤드폰 청취도 따로 확인한다.

## 다시 계획할 때 확인할 것

각 기능의 실제 필요성·적용 범위·구현 순서, 개발용/배포용 설정, 다른 PC와 기존 프로젝트 호환, 예제·사용 설명서·Python API·이벤트·그림·자동/수동 검사 및 성능 비용을 다시 결정한다. 이 문서는 사용자 요청을 잊지 않기 위한 인계이며, 지금 구현을 시작하라는 지시나 최종 기술 선택이 아니다.
