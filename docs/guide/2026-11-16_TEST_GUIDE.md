# 2026-11-16 개발 내용과 전체 수동 테스트

오늘 추가한 기능과 앞서 보류한 수동 확인을 한 번에 따라가는 안내입니다. 2026-11-16 사용자 전체 통과 보고를 받았습니다. [결과 기록표](MANUAL_TESTS.md)의 A1~A6, M1~M8과 아래 추가 확인을 포함하며, 개별 증거를 별도 수집한 결과와는 구분합니다. 다음 절차는 재검증에도 사용할 수 있습니다.

## 오늘 추가한 기능

| 기능 | 어디서 사용하는가 | 상세 사용법 |
|---|---|---|
| API → 프로젝트 DB 가져오기 | 데이터베이스 → 종류 선택 → API에서 가져오기 | [필드 연결·미리보기·적용·Undo](API_IMPORT.md) |
| API 오류 위치 설명 | 위 창의 변경 미리보기 | 응답 항목 번호·ID·응답 필드·DB 속성·오류 이유. 실패 시 전체 적용 차단 |
| 레이어 타일맵 | 장면 → 타일맵·레이어 편집 | [타일셋·레이어·표시·잠금·순서·충돌](TILEMAP.md) |
| 큰 맵 카메라 | 맵/카메라 설정 적용 → 실제 게임 실행 | 플레이어 추적·맵 경계 제한·배경/이름표 좌표 변환·화면 고정 대사/선택지 |
| 칠한 맵 크기 변경 | 타일맵 창 아래 너비·높이 → 맵/카메라 설정 적용 | 칸 좌표 유지·잘릴 타일/영역 밖 객체 수 확인·취소·전체 Undo |

[고도화 계획과 남은 후보](../REFINEMENT_PLAN.md). 외부 DB 직접 연결은 제외했고, 타일 채우기·스포이트·자동 타일·중첩 응답 연결 등은 아직 제공하지 않습니다.

## 0. 준비

PowerShell에서 저장소 폴더를 연 뒤 최신 실행 파일을 빌드합니다.

```powershell
.\dev.cmd build
```

오늘 빌드된 제작툴은 `build/windows-msvc/bin/NaruStudio.exe`입니다. 기존에 열려 있는 제작툴은 저장 후 닫고 새 실행 파일을 사용하세요. `python` 명령이 없으면 `py -3`으로 바꿉니다. 기존 프로젝트 대신 아래 테스트 전용 폴더를 사용합니다. 같은 이름 폴더가 있으면 새 이름을 정하고 이후 명령도 동일하게 바꾸세요.

## 1. API 가져오기 정상 동작 — A1~A3

PowerShell 창 하나에서 서버를 실행하고 테스트가 끝날 때까지 켜 둡니다.

```powershell
python docs/examples/api-import/server.py
```

출력 `8766`은 서버 포트입니다. 같은 포트를 쓰는 프로그램이 있으면 종료하거나 `python docs/examples/api-import/server.py 8767`로 바꾸고 아래 기본 주소도 8767로 맞춥니다. 서버는 Ctrl+C로 종료합니다.

다른 PowerShell 창에서 새 테스트 프로젝트를 만듭니다.

```powershell
& .\build\windows-msvc\bin\NaruStudio.exe --new-project build/manual-api-today
```

1. **게임 → 네트워크 접속 설정...**에서 접속 ID `local`, 기본 주소 `http://127.0.0.1:8766`을 등록하고 적용합니다. 제한 시간은 기본 10초, 헤더는 비워 둡니다.
2. **장면 → 데이터베이스**에서 **종류 추가 → 빈 데이터 종류**를 선택합니다. 표시 이름 `상품`, 종류 키 `goods`로 만듭니다.
3. **속성 정의**에서 속성을 추가합니다. 표시 이름 `가격`, 키 `price`, 형식 `정수`, 기본값 `0`을 지정합니다. 다른 속성은 추가하지 않습니다.
4. `goods`를 선택하고 **API에서 가져오기...**를 누릅니다. 서버 `local`, GET 경로 `/`, 배열 필드 빈 칸, ID `id`, 이름 `name`, 가격의 응답 필드 `price`를 확인합니다. 토큰은 비웁니다.
5. **조회 → 변경 미리보기**를 누릅니다. `potion` 회복약 120과 `ether` 마력약 250이 추가 예정으로 나와야 합니다. 아직 적용하지 않았다면 뒤의 DB 원본에는 두 항목이 없어야 합니다.
6. **프로젝트 DB에 적용**을 누르면 창이 닫히고 두 항목이 생겨야 합니다. Ctrl+Z로 함께 사라지고 Ctrl+Y로 복원되는지 확인합니다. 항목 이름과 가격도 확인합니다.
7. Ctrl+S로 저장하고 프로젝트를 닫은 뒤 `build/manual-api-today`를 다시 엽니다. 두 항목의 ID·이름·가격이 유지되면 A1~A3 통과입니다.

## 2. API 충돌·오류·취소 — A4~A6

다시 가져오기 창을 엽니다. 각 경로를 바꿀 때 **조회 → 변경 미리보기**를 다시 누릅니다.

| 순서 | 입력/조작 | 기대 결과 |
|---|---|---|
| 1 | `/`, 기존 항목 갱신 허용 끔 | `항목 1 [potion]`의 기존 ID 충돌 설명, 적용 불가 |
| 2 | 기존 항목 갱신 허용 켬 → 미리보기 | 갱신 예정으로 표시. 값이 모두 같으면 적용 버튼은 비활성 상태일 수 있음 |
| 3 | `/bad` | `항목 2 [ether]`, 응답/DB `price`, 정수 형식 오류 표시 |
| 4 | `/missing-field` | 같은 항목의 `price` 필드 누락 표시 |
| 5 | `/duplicate` | 두 번째 항목의 potion 중복 ID 표시 |
| 6 | `/missing` | HTTP 404 조회 실패. 응답 미리보기·적용 불가 |
| 7 | `/slow` 조회 직후 닫기 → 3초 이상 대기 | DB에 어떤 항목도 새로 반영되지 않음 |

오류 때 `potion`만 반영되고 `ether`는 실패하는 식의 부분 적용이 없어야 합니다. 오류 후 `/`로 되돌리고 다시 조회하면 정상 미리보기가 가능해야 합니다. 시험을 끝낸 뒤 서버를 Ctrl+C로 종료합니다. 일회성 Bearer 토큰은 이 로컬 서버에 필요하지 않습니다. 실제 HTTPS/인증 서버 연결 검증은 별도입니다.

## 3. 레이어 맵 편집 — M1~M3

```powershell
python tools/create_tilemap_example.py build/manual-map-today
& .\build\windows-msvc\bin\NaruStudio.exe build/manual-map-today
```

1. 장면 `넓은 마을`을 선택하고 **장면 → 타일맵·레이어 편집...**을 엽니다. 바닥·벽과 길·지붕의 세 레이어가 보여야 합니다.
2. 바닥 레이어를 선택하고 팔레트의 갈색 타일(1번)을 골라 드래그합니다. 한 번 드래그한 길이 한 번의 실행 취소로 사라지고 다시 실행으로 복원되어야 합니다. 오른쪽 드래그로 지워 보고 Undo도 확인합니다.
3. **추가**로 새 레이어를 만들고 이름 `테스트 장식`, 타일셋 `예제 타일`을 지정한 뒤 **레이어 설정 적용**을 누릅니다. 이름 입력만 하고 적용을 누르지 않으면 아직 문서에는 반영되지 않습니다.
4. 새 레이어에 칠한 뒤 **편집 잠금 → 레이어 설정 적용**을 누릅니다. 칠하기와 지우기가 막혀야 합니다. 잠금을 끄고 적용하면 다시 편집할 수 있어야 합니다.
5. 같은 아래 그룹의 레이어가 겹치는 위치를 칠하고 **앞으로/뒤로**를 눌러 겹치는 순서가 바뀌는지 확인합니다. 목록 아래가 나중에 그려집니다. **캐릭터 위** 설정은 별도 그룹입니다.
6. 새 레이어 삭제 확인에서 승인한 뒤 실행 취소하면 이름·타일·설정이 복원되어야 합니다. 테스트 장식을 삭제한 상태로 다음 시험을 진행합니다.

## 4. 실제 게임·충돌·지붕·카메라 — M3~M5

타일맵 창을 닫고 Ctrl+R로 실행합니다. 게임 창에 초점을 두고 방향키로 이동합니다. 편집을 바꿀 때는 게임을 닫고 수정한 뒤 다시 실행합니다. F6는 실제 충돌/카메라 시험이 아닙니다.

1. 시작점은 노란 플레이어 `(160,300)`입니다. 위로 이동해 초록 지붕 영역 `(128~288,224~288)` 안으로 들어가면 플레이어와 흰 방향 표시가 지붕에 가려져야 합니다. 지붕 레이어의 **캐릭터 위에 표시**를 끄고 적용한 뒤 재실행하면 플레이어가 지붕 앞에 보여야 합니다.
2. 시작점에서 오른쪽으로 이동하면 x=384의 회색 벽 앞에서 멈춰야 합니다. 플레이어 폭이 24라 왼쪽 위 x는 약 360에서 멈춥니다. **벽과 길** 레이어에서 회색 타일(2번)의 통과 불가를 끄면 재실행 후 통과할 수 있어야 합니다. 표시를 끈 경우에도 해당 레이어 그림·충돌이 해제됩니다.
3. 벽 아래(y=640보다 아래)를 돌아 오른쪽으로 이동합니다. 플레이어가 화면 중앙에 가까워지면 맵이 스크롤되어야 하고, 맵 오른쪽·아래 끝에서는 카메라가 멈춰야 합니다.
4. `(900,500)`의 파란 **카메라 안내원** 앞으로 가서 안내원을 바라보고 결정 키(기본 Enter/Space/Z)를 누릅니다. 이름표는 안내원에 붙어 있어야 하고, 선택지와 대사는 화면 아래에 표시되어야 합니다. `네`를 고르면 후속 대사가 나옵니다. 안내원이 없다면 최신 생성기로 새 테스트 사본을 만드세요.

## 5. 칠한 맵의 크기 변경·복원·저장 — M6~M7

게임을 닫고 타일맵 창을 엽니다. 아래 **타일 크기**는 32 그대로 둡니다.

1. 너비를 `2048 → 2560`으로 바꾸고 **맵/카메라 설정 적용**을 누릅니다. 확인 창에서 변경 전후 크기, 잘릴 타일 수, 영역 밖 객체 수를 확인합니다. 취소하면 기존 크기가 유지되어야 합니다.
2. 다시 적용하고 승인합니다. 원래 벽·길·지붕이 같은 칸 좌표에 있고 오른쪽 추가 영역이 빈 칸인지 확인합니다. 한 번 Undo/Redo로 크기와 내용이 함께 복원되어야 합니다.
   추가로 타일맵 창을 닫고 장면을 선택해 오른쪽 인스펙터의 너비·높이를 수정합니다. 타일을 칠한 뒤에도 두 입력이 활성화되어야 합니다. Enter 또는 다른 칸으로 이동하면 같은 크기 변경 확인이 나와야 하며, 취소 시 입력값 복원·승인 시 좌표 유지·Undo 복원을 확인합니다.
3. 너비/높이를 `320 × 320`으로 줄여 봅니다. 잘릴 타일 수가 표시되어야 하고, 안내원 등 밖에 남는 객체 수가 함께 나와야 합니다. 취소 후에는 문서가 그대로여야 합니다. 승인하면 밖의 타일만 제거하며 객체는 자동 삭제·이동하지 않습니다.
4. 즉시 Undo하면 잘렸던 레이어 타일과 맵 크기가 전부 복원되어야 합니다. 객체 위치·레이어 잠금·충돌 설정도 확인합니다. 최종적으로 `2048 × 1024`와 원래 내용으로 되돌린 뒤 저장합니다.
5. 프로젝트를 닫고 다시 열어 레이어·타일·충돌·크기·카메라가 유지되는지 확인합니다. 재실행해 벽과 카메라도 확인합니다.
6. 추가 확인: 모든 타일을 지운 별도 사본에서 맵을 `320 × 240`, 카메라를 `640 × 360`으로 설정하고 장면 캔버스에서 플레이어 위치를 `(80,80)`으로 옮깁니다. 게임은 좌상단 기준이며 나머지는 배경색이어야 합니다. 칠한 상태에서 타일 크기를 바꾸면 경고하고 기존 문서를 유지해야 합니다.

## 결과 전달

`A1~A6 통과, M1~M5 통과, M6 실패: 취소 후 맵 크기가 바뀜`처럼 번호와 실제 동작을 적으면 됩니다. 실패한 경우 편집기/게임 중 어느 창인지, 적용/저장/재실행 여부와 오류 문구도 함께 적습니다. 자동 검사 통과를 사용자 수동 확인으로 대신 기록하지 않습니다.
