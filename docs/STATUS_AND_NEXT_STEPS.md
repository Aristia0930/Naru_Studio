# Naru Studio 기능 점검과 다음 작업

점검 기준: 2026-11-08, 자체 C++ 엔진·Qt 제작툴·Python 스크립트. 현재 구현·검증과 앞으로의 계획을 구분합니다. 기존 [개발 순서](ROADMAP.md)와 [상세 완료 기준](DEVELOPMENT_PLAN.md)을 없애거나 순서를 바꾸는 문서는 아닙니다.

## 1. 지금 만들고 확인할 수 있는 것

| 기능 | 현재 상태 | 아직 구분해야 할 점 |
|---|---|---|
| 프로젝트·장면 | 프로젝트 생성/저장/열기, 장면·객체 배치, 플레이어·충돌·조사, Undo/Redo | 장면을 다시 들어가면 실행 중 바뀐 객체 상태는 편집 원본에서 다시 시작합니다. 게임 저장/로드는 아직 없습니다 |
| 이벤트 | 대사·선택지·변수·조건·이동·공통 이벤트·소리 등 14종, 중첩·F6·F8 | 네트워크 전용 이벤트 명령, 여러 페이지·셀프 스위치, 게임용 메뉴는 아직 없습니다 |
| 데이터·에셋 | 사용자 정의 DB와 이미지/소리 참조, 에셋 목록·그룹·ID·사용처, 객체 그림·배경·WAV/MP3 | DB 정의만으로 소지품·전투가 생기지는 않습니다. 글꼴/긴 음원 등 개별 수동 항목 전체는 통과로 기록하지 않았습니다 |
| Python | `ctx.db`, 변수, 장면 객체·입력·소리·전역 훅, Windows HTTP(S) 요청 | F5/F6에서 장면·입력·소리·네트워크는 게임 실행과 다릅니다. Python 문자열에 직접 쓴 ID는 자동 변경되지 않습니다 |
| 제작·관측 | 스크립트 줄 번호·공백 표시·들여쓰기, 로그 복사, 실제 게임 변수와 오류 위치·파일 로그 | 편집기 개선의 사용자 수동 결과와 API 실패/취소 개별 수동 결과는 아직 보고되지 않았습니다 |

**완성도:** 위 기능으로 작은 이동·대화·분기 데모를 만들 수 있습니다. 저장/불러오기, 타이틀·메뉴·엔딩, 독립 배포가 아직 없어 일반적인 게임의 완성·다른 PC 배포를 통과했다고 말할 수 없습니다. RPG·횡스크롤 기능도 이후 작업입니다.

## 2. 이번 점검과 남은 직접 확인

- 현재 빌드 및 `dev.cmd test`: **23/23 통과**(47.40초). 엔진·이벤트·DB·Python·실제 Qt 편집기·SDL 플레이어·로컬 HTTP 오류/취소·문서 검사 등을 포함합니다. 자동 검사는 각 테스트가 다루는 조건의 결과이며 모든 기능의 모든 사용 상황을 보장하지 않습니다.
- 사용자 보고: DB 이미지·소리의 안내 항목 1~6 통과, 객체 ID 변경 확인, 공개 API 응답 수신 확인. 각각의 모든 주변 조건이나 API 오류·취소까지 확인된 것으로 확대하지 않습니다.
- 사용자 직접 확인이 필요한 부분: [줄 번호·들여쓰기·로그 복사](guide/SCRIPTING.md#직접-확인하기), [네트워크 오류/F5·변수 원본](guide/NETWORK.md#5-직접-확인), 실제 스피커의 개별 음원·글꼴 예외, 다른 PC 빌드/배포. 자동 더미 오디오·로컬 서버 테스트와 별도입니다.
- 직접 테스트할 때 기존 작업 예제를 덮어쓰지 않도록 사본을 사용합니다. 현재 PC의 `build/manual-network`, `build/manual-object-id`는 로컬 사본이며 다른 PC에서는 가이드의 생성/복사 방법을 따릅니다.

## 4. 다음 단계에서 먼저 정할 규칙

네트워크 이벤트를 구현할 때 요청의 대기/계속 실행, 성공·실패 값, F6에서 실제 통신 여부, F8·장면 이동의 취소와 늦은 응답 처리를 명시해야 합니다. 현재 Python 요청은 장면 이동 시 진행 중 결과가 취소되며 F8은 자동 취소하지 않습니다. 취소는 서버에 이미 도착한 쓰기를 되돌리지 않습니다. 공통 설정에 서버 전용 비밀번호를 저장하는 방식으로 설계하지 않습니다. [현재 네트워크 규칙](guide/NETWORK.md#4-제한과-취소).

프로젝트 저장은 현재 개별 파일의 임시 저장을 사용합니다. 여러 파일 전체를 한 세대로 복구하는 기능이 완성됐다는 뜻은 아닙니다. 백업·저장 실패·복구 검증을 데이터 보호 작업으로 남깁니다.

## 5. 최종적으로 게임을 완성했다는 기준

기능 목록에 체크하는 것과 별도로, **타이틀 → 플레이 → 저장 → 앱 종료 → 다시 실행·불러오기 → 엔딩 → 개발 도구가 없는 다른 PC의 배포본 실행**을 끝까지 검증합니다. 공통 2D, RPG, 횡스크롤 각각의 구체적인 시나리오는 [상세 계획 15장](DEVELOPMENT_PLAN.md#15-게임을-완성할-수-있다의-실제-통과-기준)에 있습니다. 이 예제들은 엔진 검증용이며 사용자의 실제 게임 기획을 대신하지 않습니다.
