# 데이터베이스·에셋·Python 스킬·이펙트 연결 계획

기준: 2026-11-01. [상세 개발 계획](DEVELOPMENT_PLAN.md)을 보충한다. 사용자 추가 요구는 **DB 강화, DB에서 정의한 객체/스킬에 Python 동작 연결, 이미지·음원·스킬 이펙트의 연결, 프레임 이미지 재생과 이미지 투명화**다. 이 문서의 새 구조·동작·편집 기능은 개발 계획이며 현재 공개 API가 아니다.

## 1. 무엇을 DB에 정의하고 무엇을 실행하는가

DB는 사용자가 데이터 종류와 속성을 직접 정하는 방향을 유지한다. 캐릭터·아이템·몬스터·스킬은 편집 가능한 기본 템플릿이고, 2D 게임마다 다른 종류도 만들 수 있다.

| 구분 | 예 | 저장/실행 역할 |
|---|---|---|
| 정의 데이터 | 슬라임의 기본 체력·그림·스킬 목록 | DB에 저장하는 공통 원본 |
| 실행 인스턴스 | 맵에 나온 슬라임 1·2의 현재 체력과 위치 | 엔진이 각각 생성·변경, 필요하면 세이브 |
| 에셋 | 얼음창 그림·프레임 시트·시전 소리 | 파일은 `assets/`에 두고 DB에서는 안정적인 에셋 ID로 참조 |
| 동작 | 대상 선택·피해 계산·빙결 조건 | 기본 효과 처리 또는 명시적으로 연결한 Python 함수 |
| 표시 | 얼음창 프레임·이동·효과음·타격 시점 | 이펙트 데이터와 엔진 재생기가 처리 |

‘스킬을 만든다’는 정의와 동작을 연결하는 작업이다. DB에 행을 추가하는 것만으로 새로운 실행 규칙이 자동 생성되지는 않는다. 기본 규칙을 고를 수도 있고 Python으로 확장할 수도 있도록 만든다. 원본 정의를 수정하는 것과 전투 중 한 대상의 현재 체력을 바꾸는 것도 분리한다.

현재 구현은 기본 6형식과 이미지·소리 에셋 참조, 종류/속성/항목 편집, 이름·ID 검색, 항목 복제, 형식 변환·검증·Undo·JSON 저장, DB 읽기와 이벤트/Python 호출까지다. 아래의 스킬 연결·복합 효과·프레임/투명화 도구는 미구현이다. 기존 검색·복제도 아직 없는 기능으로 다시 계산하지 않는다.

## 2. DB 강화 작업

| 작업 | 어떻게 구현할지 | 완료 확인 |
|---|---|---|
| DB-1 목록·묶음 속성 | 스킬 목록, 능력치 묶음, 드롭 항목(아이템·개수·확률), 여러 효과 같은 반복/복합 자료를 정의. 목록 원소의 형식·참조 종류·필수값·범위를 함께 검증 | JSON 왕복·추가/삭제/순서·Undo, 중첩 오류 위치, 잘못된 원소를 검사 |
| DB-2 자료형 경계 | 현재 게임 변수의 단순 `Value`와 DB 복합값의 책임을 분리. DB용 복합 표현·JSON·Python 변환을 먼저 설계하고 목록 때문에 모든 게임 변수를 한 번에 바꾸지 않음 | 이전 프로젝트·변수·조건 비교·Python 예제가 유지됨. DB 읽기 결과는 원본을 직접 변경하지 않음 |
| DB-3 에셋·기능 참조 | 그림·음원·애니메이션·이펙트·공통 이벤트·스크립트를 종류가 있는 참조로 선택. 썸네일/재생/대상 열기 제공. 그림 칸에는 그림만 선택 | 다른 종류 선택 거부, 파일 이동/이름 변경 후 참조 유지, 누락 자료의 위치 표시 |
| DB-4 대량 편집 | 기존 항목 폼과 같은 모델을 쓰는 표 보기. 정렬·속성별 필터·열 선택·복사/붙여넣기·일괄 변경. ID와 표시 이름 분리 | 여러 적의 체력·가격 수정→오류 미리보기→적용→한 번 Undo. 선택하지 않은 항목은 유지 |
| DB-5 사용처·안전한 변경 | DB→DB뿐 아니라 장면·객체·이벤트·스킬·이펙트·UI 참조를 공통 색인으로 추적. ID/속성 변경 전 영향 확인 후 일괄 갱신 | 사용 중인 속성/스킬/그림 삭제 경고, 실패 시 일부 참조만 바뀌지 않음 |
| DB-6 가져오기·호환 | 표 형식/JSON 가져오기에서 새 항목/갱신/충돌·누락·형식 오류를 미리 보여 줌. 스키마 변경과 세이브 이행을 별도 기록 | 부분적으로 잘못된 파일을 즉시 덮어쓰지 않음. 형식 변경으로 초기화될 값 확인·취소·복구 |
| DB-7 템플릿·게임 연결 | 기본 스킬/상태/장비/적 무리/상점 템플릿과 런타임이 읽을 속성 연결 설정 제공. 임의 DB 종류도 계속 허용 | 사용자가 체력 속성의 이름/구조를 정해 연결하고 실제 캐릭터/스킬로 테스트 |
| DB-8 테스트·검증 | 항목 화면에서 참조 자료 열기, 대상/상황을 지정한 스킬 단독 실행과 결과 확인. 검사 결과에서 문제 항목/속성으로 이동 | 같은 시드/대상으로 피해·비용·상태·소리·이펙트를 재현 |

DB-5의 자동 갱신은 구조화된 참조에 적용한다. Python에서 동적으로 만든 ID 문자열까지 모두 자동 수정한다고 약속하지 않는다. 관련 스크립트 사용처와 수동 확인 필요 여부를 표시한다. 데이터 상속·계산 속성·검색용 태그/분류·고급 곡선 편집은 기본 복합값과 안전한 편집 이후 확장한다.

## 3. DB에서 Python 스킬로 연결

‘얼음창’ 예시는 다음 자료를 편집해 연결한다. 아래 항목명은 설명용이며 최종 스키마가 아니다.

| 설정 | 예 |
|---|---|
| 스킬 정의 | ID, 이름, 설명, 아이콘, 소비 MP, 사용 조건·대상 범위 |
| 기본 효과 | 피해, 빙결 부여, 지속 턴·확률 |
| 시전자 동작 | 시전 클립과 타격 신호 |
| 표시·소리 | 얼음창 이펙트, 시전음·타격음 |
| Python 연결 | 프로젝트의 스크립트 파일, 선택한 함수, 편집 가능한 매개변수 |

호출 흐름은 **스킬 선택 → 조건/대상/비용 확인 → 시전 → 타격 시점의 계산·효과 적용 → 이펙트/타격음 → 종료·복귀**다. 고정 연산과 Python 연산이 비용·피해를 중복 처리하지 않게 책임을 나눈다.

- 기본 모드에서는 엔진이 비용·대상·취소·재사용 제한을 관리하고, Python은 계산이나 효과 선택을 확장한다. 가능하면 계산 결과/효과 목록을 반환받아 엔진이 검증한 뒤 적용한다.
- 원래 동작을 바꿔야 하는 고급 스킬은 명시적인 사용자 동작 모드로 확장한다. 기본 효과와 사용자 코드가 모두 실행될지, 어느 단계가 바뀔지 설정과 문서에서 분명히 한다.
- 스크립트에는 호출별 스킬 정의·사용자 인스턴스·대상 목록·현재 게임 상황을 전달할 계획이다. 정확한 함수 인자와 엔진 API는 해당 단계에서 구현·문서화한다. 지금 존재하는 API라고 안내하지 않는다.
- 선택한 함수 이름은 연결 설정으로 엔진이 호출한다. 임의 함수 이름을 쓰기만 하면 새 자동 훅이 생기는 구조가 아니다.
- 대상이 사라지거나 사용자가 쓰러짐·장면 이동·F8·Python 오류가 발생했을 때 비용 처리 시점, 취소할 작업, 이미 적용된 결과의 보존 규칙을 정한다. 사용자 코드의 모든 부수 효과가 자동 취소된다고 약속하지 않는다.
- 탐험 이벤트·턴제 전투·횡스크롤에서 스킬을 부를 때 같은 효과/이펙트 재생 기반을 사용하고, 대상 선택/행동 순서는 장르 쪽에서 정한다.

표준 피해/회복/상태 효과는 코딩 없이 조합할 수 있어야 하고, 독특한 규칙만 Python으로 작성해도 된다. Python이 있어야만 모든 스킬을 만들 수 있는 방향으로 고정하지 않는다.

## 4. 이펙트 원본 이미지와 게임 재생

**투명한 프레임 이미지를 시간에 맞춰 재생하는 방식**부터 구현한다. 사용자는 프레임 그림 자체와 재생 데이터를 따로 편집한다.

| 가져오기 방식 | 예 | 편집기에서 할 일 |
|---|---|---|
| 낱장 프레임 | `ice_001.png` ~ `ice_024.png` | 여러 파일 선택, 숫자 순 정렬, 순서·프레임별 시간 지정 |
| 격자 스프라이트 시트 | 같은 크기 프레임을 한 PNG에 배열 | 칸 크기·행/열·사용 범위로 분리, 빈 칸 제외 |
| 아틀라스 | 크기가 다른 프레임과 각 사각형/기준점 자료 | 위치 목록 읽기, 잘라낸 여백·기준점 복원 |

권장 시작은 낱장 PNG와 격자 시트를 모두 받아들이는 것이다. 한 장으로 모으는 최적화를 먼저 요구하지 않는다. 원본 낱장 이미지는 유지하고 필요하면 빌드 때 아틀라스로 묶는다.

재생기는 이미지들을 메모리/텍스처에 준비해 두고 경과 시간에 맞는 프레임만 그린다. 프레임이 바뀔 때마다 디스크에서 파일을 읽지 않는다. 게임의 프레임 속도와 이펙트 이미지의 재생 속도는 분리한다. 예를 들어 24장을 각 1/24초로 설정하면 약 1초짜리 동작이지만 실제 기본값은 편집 설정으로 정한다.

이펙트 편집기에 프레임 목록/시간축, 재생·정지·구간 반복, 기준점, 위치·크기·회전·투명도, 레이어, 효과음·타격 신호를 둔다. 대상에 붙는 효과/월드 고정 효과/화면 효과의 좌표를 구분한다. 큰 폭발이나 여러 번 맞는 기술은 각 타격 신호를 정의하고, 피해를 매 프레임 자동 적용하지 않는다.

**캐릭터의 공격 동작, 대상 위의 스킬 이펙트, 실제 피해/회복 계산은 서로 연결하되 별도 자료/작업이다.** 타격 신호에서 효과 계산·효과음·화면 반응을 맞춘다. 정지·프레임 건너뜀·반복 재생에서도 신호가 누락되거나 같은 타격이 중복 적용되지 않게 검사한다.

## 5. 이미지 투명화·가장자리·원본 보존

| 작업 | 어떻게 구현할지 | 완료 확인 |
|---|---|---|
| ALPHA-1 투명 이미지 지원 | 가져오기·썸네일·프레임 미리보기·게임 렌더링에서 PNG 알파 보존. 체크무늬와 밝은/어두운 배경으로 미리보기 | 반투명 연기·빛·그림자, 투명 픽셀과 가장자리에서 배경색이 새지 않음 |
| ALPHA-2 단색 배경 제거 | 클릭한 배경색·허용 범위 선택. 가장자리와 연결된 영역만 제거하는 옵션, 미리보기와 적용/취소 제공 | 흰 배경을 지워도 캐릭터 내부 흰색이 함께 지워지지 않게 선택 가능 |
| ALPHA-3 마스크 보정 | 지우기/복원 붓, 확대, 가장자리 다듬기·부드럽게, 배경색 테두리 보정. 원본 위에 알파 마스크/가져오기 설정을 따로 저장 | 잘못 지운 부분 복원·Undo·재열기. 반투명 픽셀을 모두 불투명/투명으로 뭉개지 않음 |
| ALPHA-4 프레임 일괄 처리 | 여러 프레임/시트에 같은 설정 적용, 개별 프레임 보정. 공통 캔버스·기준점 유지, 여백 자르기는 원래 오프셋 기록 | 재생할 때 그림이 흔들리거나 매 프레임 크기/중심이 바뀌지 않음 |
| ALPHA-5 복잡한 배경 | 세밀한 마스크 편집과 외부 이미지 편집기 연결. 자동 분리/AI 연동은 후속 후보로 평가 | 머리카락·반투명 효과·복잡한 배경의 결과를 사용자가 비교·수정할 수 있음 |

불투명 이미지에는 숨겨진 원래 배경 정보가 없으므로 모든 배경을 정확히 자동 제거할 수 있다고 약속하지 않는다. 이펙트 원본은 가능하면 처음부터 투명 PNG로 만들도록 안내한다. 검은 배경 위 빛 효과의 더하기 합성은 투명화와 별도 설정이다. 배경색 제거만으로 반투명 빛을 정확히 복원했다고 판단하지 않는다.

원본 파일을 덮어쓰지 않는다. 원본·마스크/가져오기 설정·가공 결과의 관계를 기록하고 파생 PNG를 프로젝트 에셋으로 등록한다. 미리보기용 작은 그림과 배포용 원본 해상도를 구분한다. 에디터 이미지 처리는 Qt 이미지 기능부터 검토하고, player에는 최종 이미지와 필요한 재생 자료를 전달한다.

## 6. 원본 제작 도구와의 연결

이미지·음원·이펙트를 찾아 편집하고 다시 게임에 반영하는 흐름을 제공한다. ‘원본 열기 → 외부 수정 → 재가져오기 → 관련 DB/스킬 미리보기’가 한 작업 흐름이 되게 한다. 외부 도구 실행 경로는 PC별 사용자 설정으로 두고 프로젝트에는 개인 절대 경로를 기록하지 않는다.

이펙트의 시간축 편집·프레임 조립과 이미지 투명화는 내부 제작 기능으로 계획한다. 본격적인 그림 제작기·작곡기·음원 합성기·AI 생성 연동까지 모두 내장할지는 별도 결정이다. 생성/가공 방식에 관계없이 결과물은 같은 에셋 가져오기·참조·DB 연결 경로를 사용한다. 이미지/음원 파일의 출처·사용 권한도 에셋 정보에 기록할 수 있게 한다.

## 7. 기존 순서에 연결하는 방법

| 시점 | DB·에셋 작업 |
|---|---|
| 9 실행 관측 | DB-5의 사용처/오류 위치·전체 검사 기반부터 |
| 10 에셋·DB 연결 확장 | DB-3 이미지/소리 참조, ALPHA-1/2부터. 가져오기·목록·단순 미리보기·WAV 미리듣기·ID 유지 재가져오기는 구현(10①), 10② 객체 이미지·장면 배경·사용처·Python 이미지 변경도 구현. 10④ DB 이미지·소리 참조/미리보기/사용처/ID 갱신도 구현. 배경 제거는 후속. 다섯 번째 항목으로 외부 서버·DB 연결과 API 호출 추가(9장) |
| 11~12 맵·애니메이션 | DB-1/2 설계·구현, 애니메이션 참조, ALPHA-3/4·프레임 가져오기 |
| 13 이펙트 | 이펙트 에셋·시간축·타격 신호, DB-3 이펙트 참조, 기본 실행 미리보기 |
| 14~15 연출·저장 | DB-5/6 변경·이행·복구, 기본 효과 명령과 Python 대기 연결 |
| 16~17 RPG·전투 | DB-7 스킬/상태 템플릿과 DB-8 단독 테스트, 비용/대상/계산/이펙트까지 실제 실행 |
| 대량 콘텐츠 제작 전 | DB-4 표/일괄 편집·가져오기, 참조 안정성. 상속/공식/고급 도구는 필요에 따라 확장 |

순서 8 키 설정과 순서 9 실행 중 변수·오류 위치 이동·파일 로그까지 구현·자동 검증했고 순서 10①·②도 구현했고 이미지·ID 사용자 확인 후 10③ BGM·효과음(WAV/MP3·이벤트/Python)을 구현했다. 소리·이름표 사용자 완료 확인(2026-11-08)을 반영했으며 10④ DB 이미지/소리 속성도 구현했으며 사용자 수동 테스트 1~6과 객체 ID 변경 확인 후 10⑤의 첫 단계인 Windows 비동기 HTTP(S) Python API를 구현했다. 외부 DB 직접 연결·네트워크 이벤트 UI는 후속이다. DB 강화는 위 표처럼 전투 구현 뒤로 미루지 않고 필요한 기반부터 배치한다.

## 8. 이 연결이 완성됐다는 검증

- [ ] DB 종류·속성을 사용자가 정하고 스킬·적·아이템을 편집·복제·표 수정·저장할 수 있다.
- [ ] 프레임 이미지를 가져와 투명화·기준점·재생 시간을 수정하고, 원본 복원·재가져오기가 된다.
- [ ] 같은 이펙트를 여러 스킬에서 참조하고 원본 수정이 반영된다. 개별 스킬 수치는 독립적으로 바뀐다.
- [ ] 표준 얼음창은 코딩 없이, 별도 얼음창은 연결한 Python 계산으로 만들 수 있다.
- [ ] 비용 부족·대상 사망·시전 중 취소·Python 오류를 처리하고, 피해와 소리가 의도한 타격 시점에 한 번 적용된다.
- [ ] 맵에 배치한 적 둘은 같은 DB 정의를 쓰면서 현재 체력/상태가 서로 독립적이다.
- [ ] 스킬·그림·소리를 바꾸거나 삭제하면 사용처와 문제 위치를 찾을 수 있다.
- [ ] 게임 저장·재실행·로드·다른 PC 배포에서도 참조와 효과가 유지된다.

## 9. 외부 서버·DB 연결 확장 (순서 10의 다섯 번째 항목)

2026-11-02 사용자 요청으로 추가한 계획이다. 2026-11-08 Windows 비동기 HTTP(S) Python API 첫 단계를 구현했으며, 나머지 항목은 미구현이다. [현재 범위와 예제](guide/NETWORK.md). 순서 10의 ① 에셋 가져오기·목록 → ② 객체 이미지·장면 배경 → ③ 소리 재생 → ④ 제작툴 DB의 이미지·소리 연결 뒤, ⑤ 외부 서버·DB 연결 확장과 API 호출을 진행한다. 제작툴의 로컬 정의 DB와 외부 서비스는 별도로 두며, 온라인 기능은 필요한 프로젝트에서 선택한다. 현재 `ctx.db`가 외부 DB에 연결되는 것으로 설명하지 않는다.

| 작업 | 계획 범위 | 완료 확인 |
|---|---|---|
| NET-1 API 호출 | HTTP(S) API의 주소·경로·메서드(GET/POST/PUT/PATCH/DELETE)·쿼리·헤더·JSON 본문 설정. JSON 응답·상태 코드·오류를 이벤트/Python에서 사용. 접속 설정을 공통으로 재사용 | 검증용 서버에서 조회·전송, 한국어·빈 응답·잘못된 JSON·HTTP 오류 검사 |
| NET-2 외부 DB 연결 | 게임 → HTTPS API 서버 → MySQL 등 DB 경로를 기본 설계로 검토. 제작툴에서 외부 데이터를 가져오는 직접 DB 연결도 확장 대상으로 두되 지원 DB·드라이버·읽기/쓰기 범위는 구현 시 확정 | 로컬 제작 데이터와 서버 데이터를 구분하고, 가져오기 미리보기·형식 검사·충돌 확인 후 반영. 외부 데이터로 로컬 DB를 자동 덮어쓰지 않음 |
| NET-3 게임 연결 | 응답 필드와 게임 변수/DB 항목의 명시적 대응, 요청 데이터 전송, 이벤트 명령과 Python 호출 제공. 예: 공지 조회·랭킹 조회/등록·서버 데이터 가져오기 | 화면 설정과 Python에서 같은 요청 규칙 사용, 성공/실패 분기와 응답 반영 시점 확인. 제작툴 DB 정의 변경과 현재 게임 값 변경을 구분 |
| NET-4 실행·취소 | 게임 화면을 멈추지 않는 요청, 타임아웃·취소·실패 표시. 대기/계속 실행과 F6 테스트의 실제 통신 여부를 명시. 쓰기 요청의 자동 재시도은 중복 처리 방지 규칙과 함께 결정 | 지연·끊김·인증 실패·게임 중지·장면 이동에서 정리, 늦게 도착한 응답과 중복 전송으로 값/기록이 잘못 바뀌지 않음 |
| NET-5 인증·배포 | 개발/배포 환경별 주소·인증 설정 분리. DB 비밀번호와 서버 전용 비밀 키는 게임 배포본/프로젝트 Git/로그에 포함하지 않음. 사용자 인증 토큰의 수명·저장·가림 처리 설계 | 다른 PC에서 환경 설정 안내대로 연결, 인증 없는 요청·권한 없는 쓰기 거부, 로그와 내보내기 파일의 비밀 정보 누출 검사 |

API 호출과 외부 DB 연결은 관련 기능이지만 같지 않다. MySQL을 사용하지 않는 웹 서비스도 호출할 수 있게 하며, DB 연결만으로 멀티플레이·서버 권위 판정·클라우드 세이브 동기화가 완성됐다고 표시하지 않는다. 서버 프로그램의 제공/호스팅 범위와 첫 지원 DB는 해당 구현 단계에서 결정한다.

구현 시 접속 설정 위치, 이벤트 입력 항목/기본값/실행·대기·중지/F6 차이, Python 인자·반환·오류·호출 시점, 검증용 서버 실행 방법을 사용 설명서·이벤트 설명·SCRIPT_API·예제·그림에 함께 기록한다. 위 표는 계획 범위이며, 현재 제공하는 Python API는 [네트워크 안내](guide/NETWORK.md)와 [SCRIPT_API](SCRIPT_API.md)를 기준으로 한다.
