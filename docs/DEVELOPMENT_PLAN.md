# 실제 2D 게임 완성을 위한 상세 개발 계획

기준: 2026-11-01. 사용자 요청: 공통 이벤트까지 마무리한 뒤 개발 목록을 확장하고, 실제 게임 완성에 충분한지와 구현 방법을 다시 점검한다. 제품 범위는 **RPG도 만들 수 있는 2D 게임 엔진·제작툴**이다. 턴제 RPG·횡스크롤 지원 목표와 C++ 엔진 / Qt 제작 UI / Python 게임 확장을 유지한다.

이 문서는 개발 설계다. 아래 미완료 항목과 구조·이름은 구현된 공개 API가 아니다. 현재 체크와 다음 시작점은 [ROADMAP](ROADMAP.md), 작업 결과는 [SESSION_STATE](../SESSION_STATE.md)가 기준이다.

사용자 추가 요구인 **DB 정의→Python 동작→이미지/음원/프레임 이펙트 연결과 이미지 투명화**는 [DB·에셋·스킬 연결 계획](DATABASE_ASSETS_PLAN.md)에 더 자세히 정리했다. DB 검색·복제 등 현재 기능과 새로 강화할 부분도 구분한다.

## 1. 지금 게임을 완성할 수 있는가

**현재는 그림·소리·이동·조사·대사·선택·변수·공통 이벤트를 이용한 규칙 검증용 데모를 만들 수 있다. 게임 저장·메뉴·배포를 포함한 일반적인 2D 게임을 완성하는 단계에는 아직 도달하지 못했다.** DB에 캐릭터·아이템을 정의할 수 있다는 사실도 소지품·전투가 동작한다는 뜻은 아니다.

판단 근거는 현재 자체 엔진의 다음 코드다. Godot 실험본의 기능을 포함해 계산하지 않는다.

| 확인한 부분 | 현재 상태 | 완성에 남은 간격 |
|---|---|---|
| `engine/include/naru/project/Project.h` | 장면·객체 이미지·배경·이벤트·변수·DB·공통 이벤트 | 타일·충돌 모양·UI·게임 설정과 실행 중 상태 저장 |
| `engine/include/naru/runtime/GameWorld.h` | 탑다운 이동·조사·접촉·장면 전환·이벤트 | 장면 재진입 상태, 카메라, 동적 객체, 게임 흐름·일시정지 |
| `engine/include/naru/events/EventData.h` | 명령 14종(소리 포함), 조건·선택·호출 | 페이지·셀프 스위치·반복·이동 루트·입력·연출·장르 명령 |
| `engine/include/naru/data/Database.h` | 기본 속성 6형식과 이미지·소리 에셋 참조 | 목록·복합 효과 데이터, 게임 중 캐릭터·아이템 인스턴스 |
| `player/main.cpp` | 이미지·색 사각형·장면 배경, 한글 대사·선택지, 키보드 입력, WAV/MP3 BGM·효과음 | 카메라·범용 게임 UI·플레이어 설정·배포 로그 |
| `engine/project/ProjectIO.cpp` | JSON 검증, 파일별 임시 파일 저장 | 프로젝트 전체 저장 일관성·자동 백업·복구·버전 이행 |

기존 8~19번은 필요한 큰 줄기를 갖고 있다. 다만 **상태 유지, UI, 제작 효율, 데이터 보호, 배포와 완성작 검증**이 짧은 메모나 후보에 머물러 있어, 그 목록에 체크만 채워도 게임이 완성된다고 보장할 수 없다. 아래처럼 작업과 통과 조건으로 풀어 관리한다.

## 2. 공통 기반과 장르 기능의 경계

| 구분 | 포함할 것 | 쓰는 게임 |
|---|---|---|
| 2D 공통 기반 | 그림·소리·장면·객체·카메라·충돌·입력·이벤트·UI·저장·배포 | 탐험·어드벤처·퍼즐·스토리 게임·RPG·횡스크롤 |
| RPG 기능 | 소지품·장비·파티·성장·스킬·상태·상점·조우·턴제 전투 | RPG 기능을 사용하는 프로젝트 |
| 횡스크롤 기능 | 중력·점프·발판·이동 장애물·체크포인트·위험 지형 | 횡스크롤 프로젝트 |
| 선택 확장 | 퀘스트 전용 도구·도감·제작·낚시·파티클·고급 UI 편집 등 | 해당 기능이 필요한 프로젝트 |

일반 2D 게임의 기본 객체에 HP·장비·턴 순서를 의무로 넣지 않는다. RPG 템플릿을 선택하면 필요한 DB 정의·실행 모듈·기본 메뉴를 제공한다. 사용자가 정의하는 DB 종류·속성을 보존하고, RPG 모듈은 기본 템플릿과 속성 연결 설정을 통해 의미를 해석한다.

모든 게임에 온라인·3D·오픈월드·복잡한 물리·고급 퀘스트 도구가 있어야 하는 것은 아니다. 먼저 아래 검증용 게임을 완성하는 데 필요한 공통 기능과 장르 기본 기능을 만든다. 장르별 세부 규칙은 구현 전에 사용자와 정한다.

## 3. 구현 구조와 공통 완료 조건

- **정의 데이터:** `Project`·`Scene`과 관련 에셋/DB 정의. Qt 없이 읽고 검증할 수 있는 C++ 데이터이며 프로젝트에 상대 경로와 안정적인 ID로 저장한다.
- **실행 데이터:** 프로젝트 정의와 별개인 실행 객체·장면 상태·게임 상태. 정의 ID와 실행 인스턴스 ID를 구분한다. 삭제된 객체를 가리키는 스크립트 핸들은 잘못된 메모리에 접근하지 않고 오류를 낸다.
- **2D 객체 확장:** 먼저 위치·그림·충돌·애니메이션·상호작용·이동 방식 같은 필요한 속성 묶음을 선택적으로 붙인다. 기본 모델을 한 번에 범용 ECS로 교체하는 작업을 전제하지 않는다. 탑다운/횡스크롤 이동은 같은 객체·충돌·카메라 기반을 사용한다.
- **그리기·소리:** player가 SDL로 출력하고 에디터는 Qt로 편집한다. 게임 규칙·이벤트·UI 상태·애니메이션 시간 계산은 공용 엔진에 둔다. 이벤트 F6의 로그 미리보기와 실제 게임 실행 결과는 구분한다.
- **게임 UI:** Qt 제작툴 창과 별개로 player 안에 그린다. 레이아웃·선택·데이터 연결·포커스 규칙은 엔진, 렌더링·물리 입력은 player가 담당한다.
- **한 기능의 완료:** 데이터 검증·기존 파일 호환 → 엔진 → 편집/Undo/저장 → 코딩 없는 명령·필요한 Python 연결 → 오류·중지 → 자동 검사·실제 게임 확인 → 설명서·그림·API 문서까지 확인한다.
- **범위별 검증:** 자동 검사 통과, 사람이 화면·소리·조작을 확인한 결과, 다른 PC 실행 결과를 따로 기록한다. 화면 검사가 소리 청취나 배포 검증을 대신하지 않는다.

## 4. 입력·프로젝트 설정·게임 실행 흐름

기존 순서 8·9, 화면 관련 설정은 10~15에 연결한다.

| 작업 | 어떻게 구현할지 | 통과 조건 |
|---|---|---|
| INPUT-1 키 설정 화면 | ✅ 전용 Python 설정 파일 하나를 화면과 양방향 편집. 사용자 수정: 우선순위 대신 같은 값 동기화. 기본 조작 ON/OFF·속도·키를 저장하고 게임 시작에 사용. 실행 중 임시 변경은 원본과 분리 | 화면↔코드·탭·Undo·저장/재열기·외부 변경·실제 플레이어 키/속도/ON-OFF 자동 검증. F6의 ctx.input/player는 기존처럼 None |
| INPUT-2 게임 이용자 설정 | 제작자가 정한 기본값과 이용자 개인 키·음량·화면 설정을 분리. 개인 설정은 사용자 저장 위치에 쓰고 초기화 기능 제공 | 게임 배포 폴더가 읽기 전용이어도 설정 저장·재실행 가능 |
| INPUT-3 입력 장치와 포커스 | 키보드 우선, 게임 UI의 마우스 선택 추가, 게임패드는 그 뒤. UI가 소비한 입력은 이동·이벤트에 재전달하지 않음. 포커스 해제 때 누름 상태 해제 | 선택 결정으로 NPC 재조사/공격이 함께 나가지 않음. Alt+Tab 뒤 이동 키 고착 없음 |
| FLOW-1 게임 상태 | 시작·진행·일시정지·장면 전환·게임 오버·엔딩을 명시적인 상태로 관리. 정지 시 멈출 시간과 UI 시간·오디오 정책 분리 | 일시정지 중 이동·적·이벤트가 진행되지 않고 복귀 후 정상 재개 |
| FLOW-2 화면 설정 | 기준 해상도, 창/전체 화면, 화면 비율·검은 여백, 정수 배율/부드러운 확대를 프로젝트 기본값과 이용자 설정으로 제공 | 창 크기를 바꿔도 좌표·클릭·텍스트가 맞고 UI가 잘리지 않음 |

**8번 첫 구현 범위:** INPUT-1만 먼저 끝낸다. 게임패드·설정 메뉴·화면 시스템 전체를 한 번에 구현하지 않는다.

## 5. 에셋·그림·소리·애니메이션

기존 순서 10·12·13·14. 도트와 고해상도 그림을 모두 다룬다.

| 작업 | 어떻게 구현할지 | 통과 조건 |

| ASSET-2 🟡 참조·재가져오기 | ID 유지 재가져오기·표시 이름 변경·등록 해제/Undo·누락/변경 확인 구현. 객체 이미지·장면 배경의 사용처·제거 보호 구현. DB·이벤트의 공통 조회는 후속. 이름/경로 변경 시 ID 유지. 외부 편집 후 재가져오기와 변경 감지 | 이름 변경 후 장면·애니메이션·배포에서 그림이 사라지지 않음. 사용 중 삭제 경고 |
| ASSET-3 이미지 투명화 | 투명 PNG 알파 보존·체크무늬 미리보기→단색 배경 제거→마스크 지우기/복원·가장자리 보정→프레임 일괄 처리. 원본/설정/가공 결과 분리 | 내부의 같은 색 보존, 반투명 가장자리, 복원·Undo·프레임 기준점·재가져오기 검사 |
| DRAW-1 ✅ 기본 그림 | 그림과 충돌 영역 분리. 위치·배율·회전·투명도·뒤집기·기준점·그리기 순서 제공. 도트/일러스트 필터 선택 | 큰 그림의 발밑 판정, 겹침 순서, 고해상도 축소, 숨기기·화면 밖 제외 확인 |
| AUDIO-1 재생 | BGM/BGS/짧은 음악/효과음 채널·버스. 반복·정지·페이드·버스/개별 음량. 장면 진입 음악과 전환 정책 | 동시 효과음·BGM 반복·볼륨 변경·중지·정지 복귀를 실제로 청취 |
| ANIM-1 클립 | 격자 시트→여러 이미지→아틀라스 순으로 프레임 가져오기 확장. 프레임 시간·기준점·반복·이름 있는 클립 저장 | 프레임 수/그림 크기가 달라도 기준점 유지. 저장·재열기·미리보기 일치 |
| ANIM-2 동작 전환 | 기본 idle/walk와 한 번 재생하는 attack/cast/hurt 등 분리. 종료 복귀·이동 잠금·대기·취소와 프레임 신호 | 공격 중 이동/다른 애니메이션 요청 우선순위가 일정하고 hit 신호가 중복 실행되지 않음 |
| EFFECT-1 효과 | 시간축에 그림·위치·크기·회전·투명도·효과음·화면 신호를 배치. 대상/월드/화면 좌표를 구분 | 이동하는 대상 추적, 동시 효과, 취소·장면 전환 뒤 자원 정리 |
| PRESENT-1 화면 연출 | 그림 표시·이동·삭제, 페이드·색조·흔들림·카메라 연출. 각 작업에 끝남·대기·중지 규칙 제공 | 컷신을 중지해도 화면이 영구히 검게 되거나 조작 잠금이 남지 않음 |

이미지·소리 라이브러리 후보의 과거 버전 메모는 설치 확정이 아니다. 실제 도입 시 해당 버전·라이선스·배포 DLL·지원 형식을 검증해 BUILD 문서를 갱신한다.

## 7. 이벤트·대사·게임 상태 제어

기존 순서 11~15 사이의 공통 기반으로 승격한다. 전투 후에야 고려할 부가 기능으로 미루지 않는다.

| 작업 | 어떻게 구현할지 | 통과 조건 |
|---|---|---|
| EVENT-1 페이지·셀프 스위치 | 객체당 여러 페이지, 조건 우선순위, 객체/장면에 속한 셀프 스위치 저장. 활성 페이지 결정과 진행 중 회차의 처리 규칙 명시 | 상자를 열면 빈 상자 페이지, 퀘스트 진행 후 NPC 대사 변경, 장면 재진입·로드 후 유지 |
| EVENT-2 명령 제어 | 반복/탈출·이벤트 종료·명령 묶음·변수 계산·무작위·타이머. 먼저 구조화된 분기를 쓰고 라벨/점프는 필요도 판단 | 무한 반복 예산·중지·오류 위치를 유지하고 메뉴에서 코딩 없이 편집 |
| EVENT-3 이동 루트 | 이동·방향·대기·속도·애니메이션 단계를 하나의 경로 데이터로 저장. 반복·막힘 건너뛰기·완료 대기 옵션 | NPC 순찰·컷신 동선·문 진입을 만들고 F8/장면 이동 시 일관되게 중지 |
| EVENT-4 대기형 Python | 이벤트와 같은 고정 틱 스케줄러에 Python 코루틴 작업 연결. 대사·대기·이동 완료/실패/취소를 공통 작업으로 표현 | UI 스레드 정지 없이 기다림. F8이 자식 작업과 finally 정리를 수행. traceback 유지 |
| EVENT-5 호출과 장면 수명 | 객체에 속한 실행과 게임 전체 실행을 구분. 기존 장면 이동은 남은 명령 취소 유지. 장면을 넘어 이어갈 흐름은 명시적으로 선택 | 문 이동 중 실행 중복·오래된 객체 접근 없음. 전역 컷신만 의도한 경우 이어짐 |
| TEXT-1 대사 표현 | 이름/얼굴·창 위치·글자 속도·즉시 표시·변수 치환·줄바꿈. 넘치는 글은 페이지로 나누고 긴 선택지는 스크롤 | 긴 한국어·숫자·특수문자·큰 글꼴·창 크기 변경에서 누락·겹침 없음 |
| TEXT-2 입력·문자열 관리 | 숫자 입력·이름 입력, 텍스트 ID와 내보내기/가져오기. 한국어 조합 입력·글꼴 대체·선택 언어 지원을 단계적으로 구현 | 이름 입력 후 대사 치환, 한글 조합 취소/완료, 번역 후 분기 참조 유지 |

`async`는 예약형 `run_event`를 조용히 동기 호출로 바꾸는 작업이 아니다. 기존 API 의미를 보존하면서 기다리는 방법을 별도로 설계·문서화한다. 병렬 이벤트의 대사/선택지 창 소유권과 취소 규칙도 함께 검증한다.

| SIDE-3 상호작용·목표 | 체크포인트·수집물·문·스위치·목표 지점·피격/무적 시간·재시작. 공격/투사체는 액션을 쓰는 템플릿에서 추가 | 스테이지 사망→체크포인트→목표 도착→다음 스테이지/엔딩 |

경사·벽 타기·대시·정교한 물리·특수 이동을 모두 첫 버전 필수로 정하지 않는다. 만들 게임의 조작 규칙을 사용자와 정해 검사 지형으로 재현한다.

## 15. ‘게임을 완성할 수 있다’의 실제 통과 기준

기능 개수나 자동 테스트 개수만으로 판정하지 않는다. **기존 게임 폴더의 원본을 가져오지 않고**, 라이선스가 확인된 검증용 에셋과 별도 예제 프로젝트로 만든다. 아래 게임 내용은 엔진 확인용 제안이며 사용자의 실제 작품 기획을 대신하지 않는다.

| 검증용 게임 | 최소 플레이 흐름 | 발견해야 할 문제 |
|---|---|---|
| 공통 2D 탐험/퍼즐 | 타이틀→새 게임→두 장면 이동→대화/선택→문/스위치 퍼즐→상태 저장→앱 종료/로드→엔딩→타이틀 | 이미지·음원·UI·장면 상태·세이브·게임 종료까지 연결되는지 |
| 짧은 RPG | 마을→의뢰→상자/아이템→상점/장비→필드/던전→전투/스킬/상태→패배 재시도 또는 보스 승리→보상→엔딩 | DB 정의만 있고 플레이 기능은 없는 부분, 탐험/전투/저장 상태 불일치 |
| 짧은 횡스크롤 | 시작→이동/점프→발판/위험 영역→체크포인트→사망/재시작→장면 이동→목표 도착/엔딩 | 물리·카메라·반복 입력·부활 상태·다른 프레임 속도에서의 오류 |

각 예제는 짧은 완성 흐름부터 만들며, 규모는 검증 전에 정한다. RPG·횡스크롤 중 어느 예제를 먼저 확대할지는 사용자 제작 우선순위에 맞춘다. 지원 완료를 주장하는 장르는 해당 예제의 완주가 필요하다.

출시 가능한 제작툴 기본판으로 판단하려면 다음도 통과해야 한다.

- [ ] 제작툴 UI에서 맵·에셋·이벤트·메뉴·장르 데이터를 만들고 저장·재열기·수정할 수 있다.
- [ ] 기본 흐름은 코드 없이 만들고 사용자 고유 규칙은 문서화된 Python API로 연결할 수 있다.
- [ ] 새 게임/이어하기/설정/일시정지/재시도/엔딩/종료까지 막히지 않는다.
- [ ] 장면 재진입·저장/로드·앱 재실행 후 진행 상태가 의도대로 유지된다.
- [ ] 잘못된 에셋·참조·스크립트·세이브를 넣어도 오류 위치·이유·복구 방법을 찾을 수 있다.
- [ ] 같은 제작 흐름을 원본 소스의 수동 JSON 수정 없이 반복할 수 있다.
- [ ] 다른 PC에서 배포본만으로 실행·저장·로드·완주하며 제작툴/개발 SDK가 필요하지 않다.
- [ ] 실제 목표 규모의 데이터로 속도·메모리·반복 장면 전환·소리·글자·조작을 확인한다.
- [ ] 기본 예제·설명서·빌드/배포 절차가 함께 있고 다른 PC에서 개발도 재개할 수 있다.

## 16. 아직 결정할 것

- 첫 검증용 2D 게임의 크기·목표 PC/해상도, 실제 작품에 꼭 필요한 추가 기능.
- RPG의 전투 방식·행동 순서·능력치/효과 규칙·조우 우선순위.
- 탑다운의 자유 이동/칸 이동 범위, 횡스크롤의 조작·물리 범위.
- 기본 게임 UI의 커스터마이즈 범위, 마우스·게임패드·다국어의 첫 출시 포함 범위.
- 장면별 상태 유지 기본값과 저장 가능 지점. 기존 프로젝트/세이브 호환 정책.

지금 이 항목을 모두 먼저 확정할 필요는 없다. 가까운 구현 단위에 필요한 결정부터 하고, 결정 전 기능은 완료로 표시하지 않는다. **INPUT-1과 순서 9의 변수 관측·오류 위치 이동·호출 경로·파일 로그, 순서 10① 에셋 가져오기·목록을 구현·자동 검증했다. 순서 10② 객체 이미지·장면 배경도 구현했다. 이미지·ID는 사용자 수동 확인 완료(2026-11-08). 10③ BGM·효과음·WAV/MP3·이벤트/Python 재생을 구현했으며 소리·이름표 사용자 완료 확인(2026-11-08)을 반영했으며 10④ DB 이미지/소리 속성을 구현했으며 사용자 수동 테스트 1~6과 객체 ID 변경 확인 후 10⑤ 첫 단계로 Windows 비동기 HTTP(S) Python API를 구현했다. 외부 DB 직접 연결과 네트워크 이벤트 UI는 후속이다. BACKGROUND-1의 카메라/화면 고정 구분·작은 맵 연동과 DRAW-1의 대규모 성능/화면 밖 제외는 후속 검증이다.** DEBUG-1의 일시정지·한 틱/명령 실행·충돌 시각화, CHECK-1 전체 검사와 EDITSAFE-1 백업/복구는 아직 미구현이다.

## 17. 장면 배경 이미지와 맵 뒤의 빈 공간

사용자 추가 요구: 맵의 빈 부분이 단순히 검게 보이지 않도록 **해당 장면의 배경 이미지를 설정**한다. 장면 배경은 타일맵이나 충돌용 객체와 독립된 기본 표시 자료다. 기본 배경 이미지 1장부터 만들고 여러 레이어/시차 스크롤로 확장한다.

| 설정/구조 | 구현 계획 |
|---|---|
| 장면 저장 | 기존 `Scene.background` 배경색을 유지하고 선택적 이미지 에셋 참조와 표시 설정 추가. 이전 프로젝트는 이미지 없음+기존 색으로 호환 |
| 편집 화면 | 장면 인스펙터에서 이미지 선택·미리보기·지우기, 맞춤 방식·위치·배율·투명도 설정. Undo·저장·재열기 제공 |
| 이미지 크기 | 원본 비율 유지 ‘채우기’는 가장자리를 자를 수 있고, ‘맞추기’는 남는 부분에 배경색 사용. 원본 크기·늘리기·가로/세로 반복도 선택 가능하게 단계적 제공 |
| 카메라 관계 | 화면에 고정되는 배경과 맵 좌표에 놓이는 배경 구분. 배경 표시 범위와 플레이어가 움직일 수 있는 맵 경계를 분리 |
| 렌더링 | 배경색→배경 이미지→설정한 맵/객체/효과 레이어→게임 UI. 배경 자체에는 충돌이나 조사 판정을 만들지 않음 |
| 빈 공간 | 투명 타일·타일을 칠하지 않은 곳에서는 배경 이미지가 보임. 맵이 화면보다 작을 때도 설정한 화면 배경으로 뒤를 채울 수 있게 함 |
| 여러 배경 | 먼 하늘/산/구름의 이미지·순서·카메라 이동 비율·자동 스크롤 설정. 앞에 덮는 나무/안개는 전경 레이어로 구분 |
| 이벤트/Python | 배경 변경·스크롤·필요한 전환 효과를 명령과 API로 연결할 계획. 장면 재진입/저장 후 유지 정책은 다른 실행 상태와 일치시킴 |
| 에셋 관리 | 배경도 같은 이미지 가져오기·재가져오기·투명도·사용처 검사·배포 수집 경로를 사용. DB에 원본 이미지 바이너리를 넣지 않음 |

화면 비율을 보존하면서 생기는 창 가장자리의 검은 띠는 장면 안의 빈 타일 영역과 다르다. 프로젝트 화면 설정에서 여백 색/별도 바탕 이미지를 설정할지 정한다. 검은 띠를 없애려고 맵 그림이나 UI를 무조건 늘리거나 잘라내지 않는다.

배경 완료 검사: 빈 맵·구멍 있는 타일맵·작은 맵·큰 맵, 반투명 배경, 카메라 이동/줌, 화면 비율 변경, 이미지 누락 시 배경색/경고, Undo·저장·재열기, 배포본의 에셋 로딩을 확인한다.

## 18. 추가 점검에서 보강할 공통 규칙

기능 이름이 있어도 아래 규칙이 비어 있으면 게임 제작 중 충돌이나 반복 작업이 생긴다. 전부 새 대형 시스템으로 만들기보다 관련 기능 구현 전에 작은 작업으로 확정한다.

| 보강 항목 | 필요한 이유와 구현 범위 | 연결할 시점·확인 |
|---|---|---|
| STRUCT-1 객체 계층·붙이기 | 캐릭터에 무기·체력 표시·이펙트 붙이기. 부모 기준 위치와 월드 위치·그리기 순서·부모 삭제 시 자식 처리 구분. 부모 순환 금지 | 11~13. 이동/뒤집기/삭제/저장 후에도 붙인 위치와 수명이 맞음 |
| CONTROL-1 동작 충돌 규칙 | 기본 조작·이벤트 이동·Python·공격 동작이 같은 객체를 동시에 제어할 때 우선순위와 소유권 설정. 종료·오류·취소 때 잠금 해제 | 12~17. 컷신/공격 종료 후 이동 복구, 서로 계속 덮어쓰거나 영구 정지하지 않음 |
| LOAD-1 리소스 준비·해제 | 이미지/소리 캐시·장면 선행 준비·중복 로드 방지·불필요한 자원 해제. 느린 작업은 단계적/비동기 처리하고 화면 적용은 안전한 시점에 | 10~13. 큰 자료 로딩 중 편집기 응답, 빠른 장면 전환 후 오래된 로드 결과 적용 방지 |
| TIME-1 시간·난수 규칙 | 게임 시간·UI 시간·실제 시간을 구분. 정지/배속 중 애니메이션·음향·입력·타격 신호 정책과 엔진 난수 시드 공유 | 12~17. 정지 중 UI는 작동하고 타격/상태는 진행되지 않음. 같은 테스트 조건 재현 |
| AI-1 NPC 행동·길찾기 | 순찰/대기/추적 같은 기본 상태를 속성·이벤트/Python과 연결. 목표 위치 이동·막혔을 때 대기/포기부터, 장애물 우회 경로 탐색은 필요 시 추가 | 11~18. 막힌 목표·움직이는 장애물·추적 대상 삭제 처리. 모든 장르의 첫 버전에 고급 AI를 강제하지 않음 |
| FLOW-3 제작 시작 경험 | 빈 프로젝트 외에 기본 2D/RPG/횡스크롤 템플릿과 짧은 따라하기 제공. 에셋→맵→객체→이벤트→게임 실행→배포 경로 안내 | 15~19. 초보자가 소스/JSON 수정 없이 작은 장면을 만들고 실행 |
| SCRIPT-1 스크립트 작업 흐름 | 새 스크립트 틀·함수 연결 목록·해당 파일/행 열기·문법 검사·API 예제. 게임 실행 중 수정은 우선 재시작 시 반영, 실시간 교체는 별도 설계 | 9~17. 실행 중인 코드와 편집한 코드가 다른 상태를 표시. 오류 후 안전한 중지/재실행 |
| QUALITY-1 자동 회귀·제작 파일 관리 | CI/별도 테스트 환경에서 빌드·엔진/프로젝트/배포 검사. JSON 저장 순서·생성물 제외·프로젝트 복사/업데이트 검사 | 9~19. 다른 개발 PC·원본 관리에서도 파일 차이가 추적 가능하고 기존 예제가 유지 |

첫 검증용 게임이 요구하지 않는 온라인·3D·복잡한 물리·본격 작곡기·고급 그림 제작기까지 기본판 완료 조건으로 늘리지 않는다. 먼저 한 게임을 완주시키면서 실제로 필요한 항목을 다음 작업으로 구체화한다. 목록이 많다는 이유만으로 특정 게임에 필요한 기능이 모두 확보됐다고 판단하지 않는다.
