### P1. 게임 실행 화면(런타임 플레이어) — 진행 중

- ✅ 하위 기반: **SDL3**(창·그리기·입력) + SDL3_ttf(글자). 엔진 로직(`GameWorld`)은 SDL·Qt와 분리
- ✅ `player/` 실행 파일 `NaruPlayer.exe`: 프로젝트를 읽어 장면을 창에 그린다 (색 사각형, 장면 크기 기준 레터박스)
- ✅ 제작툴 **Ctrl+R = 게임 실행**(저장 → 현재 장면부터), 게임 → 게임 중지, 게임 로그를 로그 패널로 수신. 실행 상태는 편집 데이터와 분리
- ✅ 대사 창을 게임 화면에 표시 (DialogueHost 재사용, 결정 키로 넘기기)
- ✅ 실행 조건 일부: 자동 실행·병렬 처리 (장면 진입 시 1회)
- ✅ 입력 처리 방식 결정: **엔진이 기본 조작을 처리하고, 스크립트로 끄거나 덧붙인다** (사용자 결정 2026-10-27, RPG Maker 방식)
- ✅ 플레이어 객체 지정(장면마다 하나), 방향키/WASD 이동(대각선), 막는 객체·장면 가장자리 충돌, 통과 가능 객체
- ✅ 실행 조건: 조사(결정 키)·플레이어 접촉·이벤트 접촉(플레이어가 닿는 경우)
- ✅ 스크립트로 기본 조작 끄기/덧붙이기: `ctx.player.default_control`, `move`, `interact`, `speed`, `ctx.input.held/pressed/bind` (새 동작 포함)
- ⬜ 키 배치·이동 속도를 **설정 화면**(코딩 없이)에서 바꾸기 — 지금은 전역 스크립트의 `ctx.input.bind` **(순서 8)**
- ⬜ 병렬/자동 실행의 반복 (스위치·조건과 함께) **(순서 5)**, 클릭으로 조사
- ✅ 객체 이동(이벤트 접촉의 "객체가 닿을 때") — 스크립트 **(순서 1)**, 이벤트 명령 **(순서 2)**
- ⬜ 실행 중 변수 보기, 게임 로그의 이벤트 오류를 더블클릭하면 해당 객체·명령으로 이동 (지금은 스크립트 파일·행만 이동) **(순서 9)**
- ⬜ 게임 창 파일 로그, 배포용 글꼴 동봉 (지금은 Windows 맑은 고딕)
- ⬜ `tools/build.ps1`에 SDL3 경로 탐색 추가 (`dev.cmd`는 지원)

### P2. 공통 이벤트와 전역 스크립트

- ⬜ **공통 이벤트**: 장면에 묶이지 않는 이벤트 목록, 이벤트 명령 "공통 이벤트 호출" **(순서 7)**
- ✅ **전역 스크립트 훅**: `on_game_start`, `on_scene_enter`, `on_scene_exit`, `on_update`(매 고정 틱). 스크립트 → 전역 스크립트… 에서 등록·순서 지정
- ✅ 스크립트 호출의 **반환값 → 변수**, 이벤트에서 전역 스크립트 함수 호출(모듈 상태 공유)
- ✅ 스크립트에서 다른 객체 조작 (`ctx.scene.object(id)`, `find(이름)`, `objects()`) **(순서 1)**
- ⬜ 이벤트 시작 (`ctx.run_event`) **(순서 7)**
- ✅ **프로젝트 공용 변수 정의**: 이름·종류·초기값·설명 목록, 테스트/게임 시작 시 초기값 적용, 스위치(참/거짓) **(순서 4)**
- ⬜ 스크립트에서 대기형 동작: `async def run(ctx)` + `await ctx.say(...)`, `await ctx.wait(...)` (현재는 명확한 오류로 거부)

### P3. 이미지·음원

## 3. 게임 기능 설계 — 무엇을 어떻게 만들까

2-0의 순서 10 이후 기능들의 개발 방법 메모다 (2026-10-27 사용자 요청: 에셋·맵·애니메이션·스킬 이펙트 등 게임에 있을 만한 기능을 어떻게 개발할지 목록에). 공통 원칙: **데이터는 프로젝트 파일(JSON)에, 실행은 엔진 `GameWorld`에, 편집 화면은 Qt 에디터에, 그리기·소리는 player(SDL3)에** 둔다. 새 기능마다 이벤트 명령(코딩 없이) + 스크립트 API(`SCRIPT_API.md`) + 테스트 + 설명서를 함께 만든다.

### A. 에셋 (이미지·소리·글꼴)
- **무엇**: 게임에 쓰는 파일을 프로젝트에 넣고 관리. PNG/JPG 이미지, WAV/OGG 소리, TTF 글꼴.
- **어떻게**: 에디터 "에셋" 패널 → 가져오기(파일을 `assets/images|sounds|fonts/`로 복사), 썸네일·재생 미리보기, 이름 바꾸기, **사용처 표시**(어느 객체·이벤트·DB가 쓰는지), 없는 파일 경고. 프로젝트 데이터에는 `assets/` 기준 상대 경로로 저장.
- **엔진/player**: 이미지 읽기에 **SDL3_image**, 소리에 **SDL3_mixer** 추가(새 의존성 — 설치·라이선스 확인 후 BUILD.md에 기록). 에디터는 Qt로 미리보기.
- **스프라이트 시트**: 한 이미지를 격자(칸 너비·높이)로 나눠 프레임으로 쓴다 — C·D의 기반.

### B. 맵 (타일맵)
- **무엇**: RPG Maker처럼 타일을 칠해서 만드는 바닥·벽·장식. 지금의 자유 배치 객체와 **함께** 쓴다 (맵 = 배경 타일, 객체 = 이벤트가 있는 것).
- **어떻게**: **타일셋**(이미지 + 타일 크기 + 타일마다 통과/막힘·위에 그리기 플래그) → 장면에 **타일 레이어** 여러 장(바닥/장식/위층) → 에디터 타일 칠하기 도구(붓·지우개·사각형·채우기·스포이트), 레이어 보기 켜기/끄기. 장면 JSON에 레이어별 타일 번호 배열 저장.
- **충돌**: 막힘 타일을 엔진 충돌에 합친다 (지금의 객체 충돌과 같은 규칙).
- **나중**: 자동 타일(벽·물 가장자리 자동 연결), 큰 맵 성능(화면에 보이는 칸만 그리기), 칸 단위 이동 옵션.

### C. 캐릭터 그래픽과 애니메이션
- **무엇**: 객체를 색 사각형 대신 그림으로, 서기·걷기·공격·시전·피격 등 여러 동작으로. **도트와 고해상도 일러스트 모두** 지원 (2026-10-27 사용자: 도트가 아닐 수도 있음, 캐릭터마다 다른 동작이 필요할 수 있음).
- **애니메이션 에셋** = 캐릭터 하나의 동작 묶음 = 그림 소스 여러 개 + **클립**(이름 + 프레임 목록 + 프레임 시간 + 반복 여부) 여러 개. 특정 엔진의 소재 형식에 맞추지 않는다.
  - 클립 수 제한 없음: `idle_*`, `walk_*`, `attack_*`, `cast`, `hurt`, `die`, `victory`… 방향이 있으면 `_down/_left/_right/_up`(또는 8방향)으로, 없으면 이름만.
  - **프레임 가져오기 3가지**: ① 격자 시트(같은 크기 칸) ② **이미지 여러 장**(`attack_01.png`…, 일러스트 작업에 흔함) ③ **아틀라스**(크기가 다른 프레임을 한 장에 모은 그림 + 프레임 위치 목록).
  - 한 캐릭터가 여러 그림 파일을 쓸 수 있다(걷기 시트, 공격 시트 따로, 칸 크기 달라도 됨). 프레임마다 **기준점**(발밑 등)을 두어 크기가 달라도 위치가 튀지 않게.
  - **확대 방식**을 그림마다: 도트 = 픽셀 그대로(Nearest), 일러스트 = 부드럽게(Linear). 그림 **배율**(고해상도 원본을 줄여 쓰기).
  - **그림 크기와 충돌 판정 분리**: 충돌·조사는 객체의 사각형(예: 발밑), 그림은 기준점에 맞춰 그 위에 그린다. 그림이 커도 판정은 그대로.
  - 걷기 4방향(방향 순서·프레임 수 지정)을 한 번에 만드는 기본 틀.
- **재생 규칙**: ① **평소 동작은 자동** — 멈춤 `idle`, 이동 `walk`, 바라보는 방향의 클립(플레이어·`move`로 움직인 객체 모두). ② **한 번 재생(덮어쓰기)** — `play("attack")` → 방향에 맞는 `attack_left` 등을 한 번 재생하고 **평소 동작으로 자동 복귀**. 옵션: 재생 중 이동 막기, 끝날 때까지 이벤트 기다리기, 반복(멈춤 명령까지).
- **프레임 신호**: 클립의 특정 프레임에 이름표(`hit` 등) → 그 순간 효과음·스킬 이펙트(D) 시작·데미지 판정. 스크립트에서 받아 처리. "휘두르는 순간 맞는" 연출용.
- **스킬·공격 연결**: DB 스킬에 "사용자 동작"(예 `cast`)과 "이펙트"(예 `fire`) 속성 → 스킬 사용 시 사용자는 동작을 하고, `hit` 신호에 대상 위 이펙트 재생. 전투(순서 17)·이벤트·스크립트가 같은 방식을 쓴다.
- **편집기**: 애니메이션 편집 창 — 그림 소스 추가(시트·여러 장·아틀라스), 클립 만들기, 프레임 시간·기준점·신호 지정, 미리보기 재생(방향 바꿔 보기).
- **스크립트/이벤트**: `obj.play("attack")`, `obj.play("cast", lock=True)`, 이벤트 명령 "객체 애니메이션"(동작 이름·한 번/반복·기다리기).
- **나중 후보**: 뼈대(본) 애니메이션 — 그림 조각을 회전시켜 움직이는 방식(일러스트 캐릭터에 흔함). Spine 등 외부 형식은 라이선스 확인 필요, 자체 간단 본 방식도 검토. 무기·장비를 캐릭터 위에 겹쳐 그리기.

### D. 이펙트 애니메이션 (스킬 이펙트)
- **무엇**: 불꽃·베기·회복 같은 효과 그림을 대상 위에 재생. RPG Maker의 "애니메이션" 데이터베이스에 해당. 스킬·아이템 사용, 이벤트 연출에 쓴다.
- **어떻게**: **이펙트 에셋** = 이펙트 시트 + 타임라인(프레임마다 그림 칸·위치·크기·회전·투명도·합성 방식) + **타이밍 신호**(n번째 프레임에 효과음 / 대상 번쩍임 / 화면 흔들림 / 화면 번쩍임). 편집기에 타임라인과 미리보기(대상 더미 위에 재생).
- **재생**: 대상(객체·플레이어·화면 중앙·좌표)에 붙여 재생, 여러 개 동시. 이벤트 명령 "애니메이션 표시"(끝날 때까지 기다리기 선택), 스크립트 `ctx.effects.play("fire", target)`.
- **스킬과 연결**: 데이터베이스에 새 속성 형식 **"이펙트"**(이펙트 에셋 참조) → 스킬 종류에 `effect` 속성. 전투(H)가 스킬을 쓸 때 그 이펙트를 재생.
- **나중**: 파티클(입자) 이펙트 — 불씨·연기·반짝임을 개수·속도·수명으로 만드는 방식.

### E. 카메라와 화면 연출
- **카메라**: 화면보다 큰 장면에서 플레이어 따라가기, 맵 끝에서 멈춤, 연출용 카메라 이동(이벤트·스크립트).
- **연출**: 페이드 인/아웃, 화면 흔들림, 번쩍임, 색조, 장면 전환 효과. **그림 표시**(화면에 이미지 띄우기·이동·지우기 — 컷인, UI 장식).
- **날씨**: 비·눈 (D의 파티클을 화면 전체에).

### F. 소리
- BGM(반복 배경 음악), BGS(배경 소리), 효과음, ME(짧은 음악). 재생·정지·페이드·볼륨. 장면마다 자동 재생 BGM. 이벤트 명령 + `ctx.audio.play_se("hit")` 등. SDL3_mixer 사용(A 참고).

### G. 대사·UI·메뉴
- **대사 창**: 얼굴 그림, 이름 창, 글자 속도, 제어 문자(`\V[gold]`처럼 변수 값 넣기, 색 바꾸기), 창 위치.
- **입력**: 선택지(순서 6), 숫자 입력, 이름 입력.
- **메뉴·화면**: 타이틀 화면, 메뉴(아이템·스킬·장비·상태·저장), 상점, 게임 오버. 처음에는 고정 레이아웃 + 스크립트 확장, 나중에 **UI 레이아웃 편집기**.

### H. RPG 게임 시스템
- **저장/불러오기**: 슬롯, 게임 변수·스위치·현재 장면·플레이어 위치·소지품. 저장 형식은 JSON. (게임 변수를 권장하는 이유)
- **아이템·소지품**: DB 아이템 + 소지 개수, "아이템 증감" 명령, 조건 분기 "아이템 보유".
- **파티·능력치**: DB 캐릭터를 파티로, 레벨·경험치·능력치 성장(공식은 Python으로 바꿀 수 있게).
- **장비, 스킬, 상태 이상**: DB 종류로 정의(템플릿 제공), 효과 계산은 엔진 기본 + Python 훅.
- **턴제 전투**: 적 무리, 조우(맵 위 적 접촉 = 이벤트 접촉, 또는 무작위), 행동 순서, 명령 선택, 스킬 이펙트(D), 보상. 규칙은 사용자와 확정.

### I. 이벤트 시스템 확장

- 이미지·소리 라이브러리 (설계 A·F) — **제안: 둘 다 추가** (2026-10-27 확인: SDL3_image 3.4.8, SDL3_mixer 3.2.4 정식, 둘 다 zlib)
  - SDL3_image: PNG·JPG·BMP·GIF·WEBP·TGA·QOI(움직이는 GIF/WEBP 포함) → 바로 텍스처. 대안 = SDL 3.4 내장 PNG 읽기(의존성 없음, PNG만)
  - SDL3_mixer: 여러 소리 동시 믹싱, WAV·OGG·MP3·FLAC, 반복·페이드·트랙 볼륨 → BGM/BGS/ME/SE 모두. 에디터 미리듣기도 같은 라이브러리로. 대안 = miniaudio(직접 만들 것 많음), FMOD(상용 라이선스)
- ~~RPG Maker 그래픽 형식 호환~~ → **필요 없음** (사용자 결정 2026-10-27). 기능·작업 흐름은 RPG Maker를 참고하되 소재 형식을 맞추지 않는다
- 기본 타일 크기 — **제안: 타일셋마다 정하는 설정값, 새 프로젝트 기본 48px** (1280×720 화면에서 세로 15칸으로 보기 좋은 크기). 도트풍은 16/32, 고해상도 일러스트 배경은 64 이상도 가능. 도트가 아닐 수도 있으므로 확대 방식(픽셀 그대로/부드럽게)도 타일셋마다
- 캐릭터 그림 형식 — **제안: 일반 "그림 소스 + 클립" 방식 하나** (격자 시트·이미지 여러 장·아틀라스, 동작 수 제한 없음, 평소 동작 자동 + 한 번 재생 덮어쓰기, 프레임 신호). 설계 C 참고. RPG Maker 전용 가져오기 설정은 만들지 않음
- 스크립트 샌드박스 정책 (현재 Python은 격리되지 않은 사용자 로컬 코드)
